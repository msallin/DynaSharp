## What the fake does

`FakeDynamoDb` is for functional tests: state a test sets up and reads back through the client. For DynamoDB's fine print (validation order, messages, limits), test against an emulator or DynamoDB; a client for an emulator is `new DynamoDbClient(DynamoDbClientOptions.ForEmulator(new Uri("http://localhost:8000")))`, see [Run a local emulator](getting-started.md#run-a-local-emulator). The fake is measured against tiers 1 and 2 of the [Parity Suite](https://github.com/paritysuite/dynamodb-conformance).

### Operations

Every item operation, batch and transaction below also takes `ReturnConsumedCapacity`, and every write `ReturnItemCollectionMetrics`.

| Operation | What it does |
|---|---|
| `CreateTable` | Validates key schema, attribute definitions, indexes, projections, billing mode and throughput, and enables the stream of `StreamSpecification`. `SSESpecification` with `Enabled: true` is described as `SSEDescription` with `ENABLED`, `KMS` and a key ARN: that of `KMSMasterKeyId` (in the fake's region and account unless already an ARN), else one fixed AWS managed key. Nothing is encrypted. `OnDemandThroughput` of the table and each global index is kept and described, never enforced: each maximum is 1 to 40,000 or -1 for none, and with `PROVISIONED` it is a `ValidationException`. Table and indexes are `ACTIVE` in the answer. A taken name is `ResourceInUseException`. |
| `DescribeTable` | Current item count and size of the table and each index, `StreamSpecification` while the stream is enabled, `LatestStreamArn` and `LatestStreamLabel` of the stream enabled last, `SSEDescription` for a table encrypted with a KMS key, and `OnDemandThroughput` of the table and each global index where a maximum is set. |
| `UpdateTable` | Billing mode, provisioned throughput and on-demand maximums of the table and each global index, server-side encryption (`SSESpecification` as in `CreateTable`, `Enabled: false` back to the key DynamoDB owns), table class, deletion protection, stream on or off, and one global index created or deleted per call. A maximum left out keeps its value, -1 removes it, and a switch to `PROVISIONED` drops them all. A new index's key attributes must be in the request's `AttributeDefinitions`, not just the table's. It holds the table's items in the answer. |
| `DeleteTable` | Deletes the table and its items, frees the name at once and disables its stream. With deletion protection it is a `ValidationException`. |
| `ListTables` | Names in ordinal order, with `Limit`, `ExclusiveStartTableName`, and `LastEvaluatedTableName` when more follow. |
| `DescribeTimeToLive`, `UpdateTimeToLive` | `ENABLED` or `DISABLED` at once. Enabling twice, or disabling what is off, is a `ValidationException`. |
| `DescribeLimits` | Account defaults: 80,000 units per account, 40,000 per table. |
| `GetItem` | The item, or what `ProjectionExpression` takes of it, with `ConsistentRead`. |
| `PutItem`, `DeleteItem` | Replace or delete the item of the key under `ConditionExpression`, with `ReturnValues` `NONE` or `ALL_OLD` and `ReturnValuesOnConditionCheckFailure`. |
| `UpdateItem` | `UpdateExpression` on the item of the key, creating it from the key if missing, under `ConditionExpression`, with all five `ReturnValues` and the options of `PutItem`. Without an update expression it only creates a missing item. |
| `BatchGetItem` | Up to 100 keys over several tables, with `ConsistentRead` and `ProjectionExpression` per table. `Responses` has a list for every table requested. |
| `BatchWriteItem` | Up to 25 puts and deletes over several tables. All are written, or none if one is rejected. |
| `TransactGetItems` | Up to 100 gets at one moment: one `Responses` element per get, in order, `{}` for a missing item or an empty projection, with `ProjectionExpression`. |
| `TransactWriteItems` | Up to 100 condition checks, puts, deletes and updates over several tables, all or nothing, with `ClientRequestToken`. |
| `Query` | One partition of the table or an index by `KeyConditionExpression`, in sort key order (reversed with `ScanIndexForward: false`), with `FilterExpression`, `ProjectionExpression`, `Select`, `Limit`, `ExclusiveStartKey` and `ConsistentRead`. |
| `Scan` | Every item of the table or an index, or of one `Segment` of `TotalSegments`, with the options of `Query` except key condition and direction. |
| `ListStreams` | The streams of all tables or of the one named, in the order enabled, with `Limit`, `ExclusiveStartStreamArn`, and `LastEvaluatedStreamArn` when more follow. A table without a stream, an unknown table or an unlisted `ExclusiveStartStreamArn` gives an empty list. |
| `DescribeStream` | Status, view type, key schema and the shards in the order of their ids, each with its `ParentShardId`: open (no `EndingSequenceNumber`) while the stream is enabled and the shard has not split, closed then. `ExclusiveStartShardId` and `Limit` page the shards, with `LastEvaluatedShardId` when more follow. `ShardFilter` with `CHILD_SHARDS` lists the children of the shard it names. A shard closed 24 hours ago is not listed, nor a child before its time to be listed has come. |
| `GetShardIterator` | `TRIM_HORIZON` (oldest record kept), `LATEST` (after the newest), `AT_SEQUENCE_NUMBER` and `AFTER_SEQUENCE_NUMBER`. `AT_SEQUENCE_NUMBER` at the `StartingSequenceNumber` of a shard reads from its first record kept, and is `TrimmedDataAccessException` once a record of it is trimmed. `SequenceNumber` with `TRIM_HORIZON` or `LATEST` is a `ValidationException`. A shard closed 24 hours ago is `ResourceNotFoundException`. |
| `GetRecords` | Records from the iterator on, up to `Limit` (default 1,000) and 1 MB, and `NextShardIterator`, left out on the last page of a closed shard. An open shard read to its end gives an empty page with a next iterator. |

### What a test can rely on

- **Consistency.** Every read, and every index, sees the last write, with or without `ConsistentRead`.
- **Keys and sizes.** A key with an attribute too many, too few or of the wrong type is `The provided key element does not match the schema`, as is such an item of `BatchWriteItem`; an item of `PutItem` or a transaction gets `Missing the key pk in the item` or the type mismatch. Empty strings and binaries in a key are rejected. An index key attribute whose type differs from its definition is a `ValidationException`. Limits: partition key 2048 bytes, sort key 1024, of the table and of an index (`Size limit exceeded`), item 400 KB, sized as the Developer Guide counts.
- **Indexes.** An item is in a secondary index if it holds all of the index's key attributes, projected by `ALL`, `KEYS_ONLY` or `INCLUDE`. A global index created by `UpdateTable` leaves out items whose index key is of another type, empty or too large.
- **Numbers and sets.** Numbers keep 38 significant digits, from `1E-130` to below `1E+126`, and return in canonical plain digits: `01.50` as `1.5`, `1E+2` as `100`; key `1.0` is key `1`. Sets return strings and binaries in byte order, numbers by value. Sets with a duplicate and documents nested deeper than 32 levels are rejected.
- **Order.** Sort keys order strings by UTF-8 bytes, binaries by bytes, numbers by value. Partition order is fixed per run; do not depend on it.
- **Paging.** `Limit` counts the items read, before the filter, and a page also ends at 1 MB read, by item size. A page cut by either carries `LastEvaluatedKey`, even when nothing follows or the filter dropped every item, so an empty page need not be the last. The key holds the table key, plus the index key for an index read. `ExclusiveStartKey` must be such a key, within the partition and sort key range of a query or the segment of a scan; an empty one is a `ValidationException`.
- **Count and Select.** `Count` is the items that passed the filter, `ScannedCount` the items read. `Select` defaults to all attributes on a table, projected ones on an index, named ones with a projection. A local index fetches from its table what it does not hold. A query filter may read only what the index projects; a scan filter on an index sees the table item. `ValidationException`: `SPECIFIC_ATTRIBUTES` without a projection, a projection with any other `Select`, `ALL_PROJECTED_ATTRIBUTES` on a table, `ALL_ATTRIBUTES` on a global index that does not project everything, a projection naming an attribute a global index does not project (`Global secondary index <name> does not project [<attributes>]`), a query filter on an attribute the index does not project (`Secondary index <name> does not project one or more filter attributes: [<attributes>]`), a query filter on a key attribute, and `ConsistentRead` on a global index.
- **Parallel scan.** Each item is in exactly one segment, fixed per run; do not depend on which.
- **Projection.** Takes the paths it names, nested ones and list elements included, and the key only if named.
- **Read capacity.** As in the Developer Guide: 1 unit per 4 KB, rounded up, at least 1, halved when eventually consistent. `GetItem` pays for the whole item, whatever it projects, and for a missing one; `Query` and `Scan` for the items read before the filter. With `INDEXES`, index reads are reported under the index, the table at 0 or at what a local index fetched.
- **Expressions.** Grammar and type rules are those of the Developer Guide. Comparing different types is false. `<`, `<=`, `>` and `>=` take strings, numbers and binaries. `size` of a string counts UTF-16 code units; a number, boolean or null has no size, so comparing it is false. `ValidationException`: a bare reserved word, a placeholder missing from `ExpressionAttributeNames` or `ExpressionAttributeValues`, a map entry no expression of the request uses, doubled parentheses such as `((a = :v))`, and `contains` with the same path twice.
- **Failed conditions.** `ConditionalCheckFailedException` with `The conditional request failed`, holding the old item under `ReturnValuesOnConditionCheckFailure: ALL_OLD`. An update cannot change a key attribute. `SET` of list indexes past the end appends in index order: `SET l[11] = :b, l[10] = :a` on `[x, y]` gives `[x, y, :a, :b]`.
- **ReturnValues.** `PutItem` and `DeleteItem` take `NONE` or `ALL_OLD`; anything else is a `ValidationException`. `ALL_OLD` and `ALL_NEW` are the whole item before and after. `UPDATED_OLD` and `UPDATED_NEW` are the paths the update named, nested ones inside their parents (`SET a.b = :v` gives `a` with `b` alone); `UPDATED_NEW` leaves out paths only a `REMOVE` named. `Attributes` is left out when there is nothing to return, such as `ALL_OLD` of a new item.
- **Write capacity.** 1 unit per KB of the larger of the item before and after, rounded up, at least 1, also for deleting a missing item. A secondary index adds 1 for an item entering or leaving it, 2 when its index key changes, 1 when a projected attribute changes, else 0. A transaction pays double per item, a condition check as a write of the item it reads; a transactional read is double a strongly consistent read. A batch rounds each item on its own. Batches and transactions report one `ConsumedCapacity` per table. With `INDEXES` a transaction also reports its units as `ReadCapacityUnits` (`TransactGetItems` and a replay) or `WriteCapacityUnits` (`TransactWriteItems`), at the top, per table and per index.
- **Item collections.** `ReturnItemCollectionMetrics: SIZE` reports the collection of the partition key written, with `SizeEstimateRangeGB` `[0, 1]`, for a table with a local secondary index, and nothing otherwise.
- **Batches.** More than the limits above, a key twice, or a write with both or neither of `PutRequest` and `DeleteRequest` is a `ValidationException`. `UnprocessedKeys` and `UnprocessedItems` are always empty (see the README above).
- **Transactions.** Every condition is checked against the items as they were before. If one fails, nothing is written and it is `TransactionCanceledException` with one `CancellationReasons` entry per action, in order: `ConditionalCheckFailed`, with the item where `ALL_OLD` asked; `ValidationError` for an action the item cannot take (such as an update past 400 KB) and for a key that does not match its table's schema; `None` for the others. An empty string or binary in a key or an index key attribute, or a too large index key, fails the whole request with `ValidationException` instead of a reason. One item twice is a `ValidationException`.
- **Idempotent transactions.** `ClientRequestToken` makes `TransactWriteItems` idempotent for 10 minutes on the constructor's clock. The same token with the same request changes nothing, succeeds and reports double a strongly consistent read of each item; with another request it is `IdempotentParameterMismatchException`. A cancelled transaction does not keep its token. `Reset` forgets every token.
- **Stream records.** Each change of an item is an `INSERT`, `MODIFY` or `REMOVE` record, in write order with ascending sequence numbers, with the images of the view type: keys for `KEYS_ONLY`, the item after for `NEW_IMAGE`, before for `OLD_IMAGE`, both for `NEW_AND_OLD_IMAGES`. A write that changes nothing, such as the same `PutItem` again, records nothing. A transaction or batch records its changes together, a failed request none, the direct API as a request does. A record exists by the time its write answers. `SizeBytes` is the size of keys and images, counted as item sizes; `ApproximateCreationDateTime` is the fake's clock in seconds.
- **Stream lifecycle.** Each enable by `CreateTable`, `UpdateTable` or `EnableStream(table, viewType)` makes a new stream, with a new `LatestStreamArn` and `LatestStreamLabel`; changing the view type takes one `UpdateTable` (or `DisableStream(table)`) to disable and one to enable. `ValidationException`: enabling an enabled stream, disabling one that is off, `StreamEnabled: true` without `StreamViewType`, and `StreamEnabled: false` with one. A disabled stream, also of a deleted table, stays readable and listed for 24 hours; then `ListStreams` omits it and reading it is `ResourceNotFoundException`. A stream enabled after `Reset` has a new ARN, also on the same clock, so an older iterator is `ResourceNotFoundException`.
- **Shards.** `CreateStreamsClient()` makes a client that waits on the clock of the fake, so `EmptyPageDelay` and the looks of `ReadStreamAsync` pass as the test moves it; `configure` can set another clock. Those waits also end at the next change of a stream of the fake, a write, a split, an enable or a disable, so a reader on the system clock reads a write at once. A test that measures `EmptyPageDelay` reads through a client of `StubClient.CreateStreams` instead, see the README above. A stream starts with one shard. `SplitStreamShards(table, children, secondChildListedAfter)` ends every open shard and opens one child of each (a rollover) or two (a split); the children take the writes from then on, each the items of its share of the partition keys, so the changes of an item stay in order along the lineage. With `secondChildListedAfter` the second child takes writes at once and is listed only once the clock has moved on by that much, which is how DynamoDB can list a child late. A shard closed for 24 hours is gone, with its records.
- **Iterators.** Valid 15 minutes on the constructor's clock, then `ExpiredIteratorException`; every page hands out a new one. Records are kept 24 hours; an older position is `TrimmedDataAccessException`. A sequence number outside the shard's range, or a text that is no iterator, is a `ValidationException`.
- **Time to live.** `ExpireItems()` records each delete as a `REMOVE` with the `userIdentity` `{"Type":"Service","PrincipalId":"dynamodb.amazonaws.com"}`, as DynamoDB records time to live deletes. A client's delete has none. It sweeps tables with time to live on, which `CreateTable<T>` turns on for an entity with `[TimeToLive]`.
- **Entities in the direct API.** `Items<T>` of an entity with a discriminator reads only the items whose discriminator attribute, `_type` or the one the entity names, is a string equal to its discriminator, as `Item.Is<T>()` tests, and skips every other item: those of other entities and those without the attribute, which a typed `Scan()` filters out too. An item of the entity that it cannot read throws `DynamoDbMappingException`. An entity with `[Discriminator(OptOut = true)]`, and a document such as `Item`, have nothing that tells items apart, so `Items<T>` reads every item, and one it cannot read throws. `Get<T>` reads the one item of its key and throws for an item of another entity, as `Get(key).ItemAsync()` does.
- **Error responses.** HTTP 400 with DynamoDB's code in `__type`, so the client throws what it throws for DynamoDB. Every answer carries `x-amzn-RequestId`.

### What the fake is not

- Nothing throttles: provisioned throughput is stored and reported, never enforced. Faults come from `FailNext` or from the handler, as in the README above.
- No automatic expiry: see `ExpireItems()` in the README above.
- No PartiQL, backups, point-in-time recovery, export or import, tags, resource policies, global tables, warm throughput, Contributor Insights or Kinesis destinations.
- Shards split only when `SplitStreamShards` says so, never by themselves. A stream is `ENABLED` or `DISABLED` at once, never `ENABLING` or `DISABLING`.
- Not concurrent: no `TransactionConflict` or `TransactionInProgress`, and a batch is as atomic as a transaction.
- Not the fine print: the exact validation order, the wording of every message, the 10 GB item collection limit and its exact size estimate, the 16 MB batch limit, `x-amz-crc32` as a checksum.

### How it answers what it does not do

It fails loudly, never silently.

- An operation it does not answer, such as PartiQL: HTTP 400 with `UnknownOperationException` and `FakeDynamoDb does not implement <Op>. It is not supported.`
- A member it does not implement in an operation it answers: HTTP 400 with the code `UnsupportedByFakeException` (in `DynamoDbException.ErrorCode`) and a message naming the member and the operation. In item operations, batches, transactions and reads these are the legacy parameters: `AttributesToGet`, `AttributeUpdates`, `Expected`, `KeyConditions`, `QueryFilter` and `ScanFilter`. In table operations: tags, and any member the fake does not know, such as `WarmThroughput` or `ReplicaUpdates`.
- A value DynamoDB rejects gets DynamoDB's `ValidationException`, also where the fake implements little: an enum value DynamoDB lacks, such as `"AttributeType":"BOOL"`; `ExpressionAttributeNames` or `ExpressionAttributeValues` without an expression; a legacy parameter together with an expression (`Can not use both expression and non-expression parameters in the same request`).

## Locks

A `LockTable` of [`DynaSharp.Coordination`](coordination.md) runs on a client of the fake, over a table that `fake.CreateTable("Shop", "pk", "sk")` creates, and the extensions of `DynaSharp.Coordination.Testing` let a test do what another process would: hold the lock (`SimulateHolderAsync`), release it (`SimulateReleaseAsync`) or delete its item (`SimulateDeleteAsync`), and check what happened: the state of the lock (`GetStateAsync`) and a contender that was turned away (`WaitForRefusalAsync`), without knowing the format of the item. They live in the Coordination package, so `DynaSharp.Testing` does not depend on it. See [Testing](coordination.md#testing) in the guide of the locks.
