## Findings and gotchas

Tools:
- Stryker 5 with the MTP runner (preview for TUnit) flips mutants in static initializers and near timeouts between Killed, Timeout and Survived across runs; hand-check a survivor before acting. A local run of a few files still pays the per-test coverage capture of the whole suite (about 19,300 tests), longer than a 30-minute background job. After a run, `bin/` may hold a mutated assembly: `dotnet test` rebuilds, direct DLL runs do not.
- A coverage run instruments the assemblies of its `bin` in place: a test run from the same `bin` meanwhile fails with `BadImageFormatException`; loop beside it from a copy.
- A test run with `--no-build` after a failed build reports the old binaries: check the build exit code. TUnit accepts one `--treenode-filter`. Semaphore-gated tests hang instead of failing on a regression: run with `--timeout`.
- BenchmarkDotNet builds its child project from the process start directory, not `--project`: start it in the worktree. A `sealed` benchmark class is rejected while the run exits 0: check `executed benchmarks: N` with N > 0. BenchmarkDotNet 0.15 does not know `net11.0`; 0.16.0-preview is pinned.
- SDK rc.3: `dotnet publish -o` fails copying the XML doc file of an executable (`PublishDocumentationFile=false` in the AOT smoke). File-based apps default to Native AOT (`build/CoverageGate.cs` sets `PublishAot=false`). Native AOT on Windows needs the C++ workload; otherwise run the `linux-x64` gate in a container. Library projects list the same `RuntimeIdentifiers` so the AOT publish does not change their lock files.
- Visual Studio without the pinned SDK empties the lock files of an open checkout (`"net11.0": {}`).
- Some tools turn `\uXXXX` escapes into characters, and `dotnet format whitespace` sees line endings: write escaped JSON programmatically and check files after writing. PowerShell `[IO.File]` resolves relative paths against the process start directory.
- JFrog: after a release `registration-semver2` of a virtual feed lists the old version for over an hour; seed the global NuGet cache with nuget.org's own nupkgs (not the GitHub release files, which nuget.org re-signs).
- Coverage-gate traps: a method-group conversion at several call sites creates `??=` cache branches (use one static delegate); a string `switch` of 7 or more cases lowers to branches no test reaches (architecture 13); a method on a generic `T` with a property call as argument gets a hidden branch (pass a local); an async iterator with `while (cond)` around a `yield` leaves a branch (`while (true)` with `yield break`, `for` over an `IReadOnlyList`). Coverage flakes came from timing in stream and lock tests; hold the path open in the test instead of racing it.
- TUnit registers a global `ActivityListener`, so `StartActivity` never returns null in tests; the null path uses an injectable `ActivitySource`. Telemetry tests isolate by trace id, table or `server.address`; a counter without a table tag allows one test per operation.
- Tests must not depend on `ArrayPool<byte>.Shared`: inject a counting pool and assert every rented array is returned once.
- `Utf8JsonReader`'s default `MaxDepth` 64 is too low (32 DynamoDB levels are 64 JSON levels plus the envelope): the reader uses 128. `CancellationTokenSource.TryReset` is true only for `TimeProvider.System` timers. `Task.Delay(TimeSpan, TimeProvider, ct)` truncates to milliseconds and completes at once for 0. `cond ? x : null` on `ReadOnlyMemory<byte>?` gives empty, not null. A nested pool rent misses the thread cache (about 30 % CPU on Query), so item scratch lives on the stack; plain FNV collapses on names like `attribute07`, so the hash has a MurmurHash3 finalizer.
- `SetActivityTags` must never throw (the span starts before the `try`). Internal converter classes trigger CA1812 in consumers; doc examples use `public sealed class`. `Select` as a type name is CA1716, suppressed (service name).
- `ClientConfiguration.Resolve` without a region and a reader reads the machine's shared files: tests set a region or pass a reader. `TestClient.Create` defaults to `maxAttempts: 1`.
- Docker: the Dynoxide image tag on `ghcr` is `1.5.0` without `v`; Testcontainers also pulls `testcontainers/ryuk` from Docker Hub.

Behaviour worth knowing (documented, by design):
- After a lost response, a retried conditional or versioned write fails its own condition although the first attempt applied; `RetryOnConflictAsync` then applies the change again. `.MaxAttempts(1)` on the write avoids it; the library cannot tell a duplicate delivery from its own retry (compare the item of `ReturnOldOnFailure()`).
- `IfVersion(n)` checks `long`, so an `int` version past its maximum stores a value that later fails to read; `Delete(entity)` reads a `ulong` version above `long.MaxValue` before `IgnoreVersion()` and throws.
- A custom converter on a plain key that writes binary, or a number without `IAddableConverter`, is created as a string key, and the first put fails; `ToRequest()` is the way out. Two tables whose keys have the same names cannot be told apart by `IncludingAll()`.
- A provider the application created judges expiry on the local clock and recovers through one rejected request; client-owned providers use the corrected clock. `ExpiredTokenException`/`ExpiredToken` drop the credentials and resend once (codes from `credsExpiredCodes` of the AWS SDK for Go v1; botocore lists none for DynamoDB). IPv6 IMDS and `AWS_SECURITY_TOKEN` are not supported.
- A `credential_process` whose credentials expire within 10 minutes runs on every call (they are in the mandatory window at once), as in botocore.

botocore and reference facts:
- botocore keeps inline `#` comments in values, inherits `[DEFAULT]` into every section, matches `[profile x]` by prefix and splits it like a shell, and fails the whole file on a bad nested block. Chain: env, assume role, web identity, SSO, credentials file, login, process, config file, container, IMDS.
- Deviations from botocore: container and IMDS treat an empty variable as unset, trim a token file, reject `FULL_URI` with user info and never echo URIs; SSO portal and OIDC get 3 attempts (botocore legacy: 5); a missing `AWS_PROFILE` profile stops the chain; the environment is its own source ahead of the shared files (botocore reads web identity keys from env and profile key by key); `duration_seconds` outside 900..43200 fails; session names default to `dynasharp-<unix time>`.
- botocore has no clock-skew correction (the oracle is the AWS SDKs), does not know `ConsumedCapacity.VectorIndexes`, validates `Limit >= 1` client-side, and parses only `Message` of `TransactionCanceledException`. The API reference's `BatchGetItem` response sample is invalid JSON; its `DescribeStream` sample prints a date string where the service sends epoch seconds; `Record.Region` is `awsRegion` on the wire.
- The AWS SDK's `DateTime` conversion (V1 and V2, `AWSSDK.DynamoDBv2` 4.0.109, run on UTC+1): `ToUniversalTime()` as `yyyy-MM-ddTHH:mm:ss.fffZ`, `Unspecified` taken as local; `DynamoDBContext` reads `Utc` by default. `SdkDateTimeConverter` does the same.

Real DynamoDB, from the first runs of `real-aws.yml` (beyond the Fidelity answers below):
- A global index lags its table with no documented bound (1.6 to 1.9 s seen): `SettlingHandler` holds a read of an index 5 s after the last write, of a table 1.5 s. The recipes that read an index right after a write hold on emulators only.
- A scan rounds each partition up to 4 KB, so a new on-demand table of several partitions reports more than a query of the same items.
- `BatchGetItem` and `BatchWriteItem` leave keys and items unprocessed when a partition runs out of throughput, not only at 16 MB.
- An index that `UpdateTable` adds takes 8.5 to 15 minutes even on a tiny table (allocated before backfill); `DeleteTable` is refused with `ResourceInUseException` meanwhile (`Tables.IndexBuildTime` is 30 minutes). A second time-to-live change within an hour is refused; a deleted table stays `DELETING` and keeps its name a while; a stream may have several shards (`Gap.TimeToLiveChangesAgainAtOnce`, `TableGoneAtOnce`, `OneShardPerStream`).
- `UpdateTable` twice within a second throttled on all four attempts. An exception from `DisposeAsync` under `await using` replaces the test's own: `Sandbox` hands cleanup failures to `CleanupFailures` and its hook decides with the test result.
- Real DynamoDB accepts empty strings as members of `SS` and `BS` (Parity Suite captures). TTL deletion lags "a few days"; one item takes about 1000 WCU/s; a write is billed on the larger of its before and after images.

### What the fake follows (decided)

- An expression with the same operand twice (`a = a`, `a BETWEEN a AND :v`, `begins_with(a, a)`, ...) is a `ValidationException`; so are a `BETWEEN` bound that is no S, N or B, redundant parentheses (`((a = :v))`), and a legacy parameter beside an expression.
- The item of a write is checked before its condition (index key of another type, empty index key, over 400 KB); in a transaction a put of a mistyped index key is a `ValidationError` whatever its condition, and an index key over 2048 (partition) or 1024 (sort) bytes fails the whole request.
- A read is at least 1 unit (0.5 eventually consistent); with `INDEXES` an index read reports `Table` with 0 units; a condition check in a transaction costs 2 units; an index entry is sized without the 100 bytes of overhead; a number of 39 digits is a plain `ValidationException` even in a transaction. A 1 MB page ends with the item that passes 1 MB.
- Projections and filters of an index on attributes it does not project are `ValidationException` in `Query` (and projections in `Scan`); the filter of a `Scan` of an index sees the table item; a local index fetches from the table. A global index that `UpdateTable` creates leaves out items whose index key is empty, mistyped or too large.
- `SET l[11] = :b, l[10] = :a` on `[x, y]` appends in index order; `REMOVE l[i]` past the old end does nothing; `REMOVE a.b` without `a` is "The document path provided in the update expression is invalid for update".
- Streams: records commit at the end of a request and drop with it; no record for an unchanged item; `SizeBytes` as the Developer Guide's example; records trimmed after 24 hours, a closed stream gone 24 hours after closing, iterators expire after 15 minutes (exactly 15 is expired); `ListStreams` of something unknown answers `"Streams":[]`; `UpdateTable` checks the shape of `StreamSpecification` before the table's state.
- From the vectors of DynamoDB Local: `size` of a string counts UTF-16 code units; `size` of a scalar is no error (a filter matches nothing, a condition fails); `a <> :v` holds on a missing attribute or another type; constant operands (`size(:v)`, `:v = :w`) evaluate, and a constant of the wrong type is rejected before the item, also for `<`; a key condition on a non-key attribute or the sort key alone is "Query condition missed key schema element"; an empty sort key value is rejected like an empty partition key; the messages of `Vectors/messages.json`.
- `OnDemandThroughput`: described only when a maximum is set; `-1` removes one (and means none in `CreateTable`, as the reference allows); one member alone is allowed; 0 or below -1 and above 40,000 are rejected with Local's messages; with provisioned capacity Dynoxide's messages; an empty object or an index `Update` without either throughput gets a message of the fake's own.

Only real DynamoDB answers these; the fake's current choice is in brackets.
- Queries: the `LastEvaluatedKey` rule above (Open); whether a filter on a non-projected attribute of a local index fetches from the table [rejected, as Local]; whether a `Scan` of an index rejects such a filter [evaluates on the table item, as Local]; the order of attributes in "Global secondary index <name> does not project [...]" [order of the expression]; `GetItem` of a projection that matches nothing [`{}`, an emulator answers `Item:{}`].
- Updates: the index of an appended element in `UPDATED_NEW`/`UPDATED_OLD`; the type check of a constant operand of `-`; the distinct-operand rule of functions beyond those listed above; whether an empty index key of a transaction is found before the conditions.
- Capacity: whether `TOTAL` also splits a transaction's units into `ReadCapacityUnits`/`WriteCapacityUnits` [only with `INDEXES`].
- `OnDemandThroughput`: an unset maximum reported as absent or -1 [absent]; -1 or one member in `CreateTable`; the messages of an empty object and of an index `Update` without throughput; rejecting it on an index of a provisioned table [rejected]; maximums over a switch to `PROVISIONED` and back.
- Encryption: `SSEType: AES256` in `CreateTable` [reports `KMS`]; `Enabled: false` with a key; an alias as `KMSMasterKeyId` [reported as the alias's ARN]; `SSESpecification` in `UpdateTable` naming the current encryption [accepted]; the description after switching back to the AWS-owned key [`SSEDescription` dropped].
- Streams: a sequence number above the last record of an open shard [`ValidationException`]; an unknown `ExclusiveStartStreamArn` while streams exist [empty page]; the message of a missing `SequenceNumber`; reading a child at its starting sequence number (Open).
- Numbers and names: `1E-07` and other exponent forms as `N` text (emulators normalize; `+5`, `.5`, `5.` and `0005` pass, whitespace, `0x10`, `1_000` and `1,5` do not); a bare name starting with `_` [syntax error].
- Messages not mimicked: empty sets (emulators: "One or more parameter values were invalid: An string set  may not be empty"), duplicates in a set ("Input collection contains duplicates"), an update past 400 KB ("Item size to update has exceeded the maximum allowed size"). Which fault of several is reported first differs in places; `docs/testing.md` lists the validation order as fine print.
- Harness limits: no local secondary index, no stream reads, no `ReturnItemCollectionMetrics`, GSI sort numbers from a small pool, the 1 MB cut compared only on ordered queries.
