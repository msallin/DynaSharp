# DynaSharp - public API

The public API as shipped, and the contract for changing it. A change to the public surface changes this file in the same commit; a change of contract goes through the lead. The key grammar is in `requirements.md`, the compile-time rules in `../docs/diagnostics.md`, the internals in `architecture.md`, the user guide in `../docs/`. The XML docs say what each member does; this file says what the surface is and which rules hold across it.

The surface is tracked by `Microsoft.CodeAnalysis.PublicApiAnalyzers` (build time only) on `DynaSharp`, `DynaSharp.Testing` and `DynaSharp.Coordination`: `PublicAPI.Shipped.txt` holds what is released, a change goes into `PublicAPI.Unshipped.txt`, and `RS0016`/`RS0017` fail a build that does not say so. Before a release `build/ship-public-api.sh` moves the lines to Shipped; the release workflow refuses to run while any are left.

Examples use this model.

```csharp
public enum OrderStatus { Open, Shipped }

[DynamoDbDocument]
public partial record Address(string City, string? Zip);

[DynamoDbEntity]
[Discriminator("ORDER")]
[PartitionKey("USER#{UserId}")]
[SortKey("ORDER#{OrderId}")]
[GlobalIndexKey("StatusIndex", PartitionKey = "STATUS#{Status}", SortKey = "{PlacedAt}")]
public partial record Order
{
    public required string UserId { get; init; }
    public required Guid OrderId { get; init; }
    public required OrderStatus Status { get; init; }
    public required DateTimeOffset PlacedAt { get; init; }
    public decimal Total { get; init; }
    public int Lines { get; init; }
    public Address? ShipTo { get; init; }

    [Version]
    public long Revision { get; init; }
}

[DynamoDbEntity]
[Discriminator("CUSTOMER")]
[PartitionKey("USER#{Id}")]
[SortKey("PROFILE")]
public partial record Customer
{
    public required string Id { get; init; }
    public string? Email { get; init; }
    public int OrderCount { get; init; }
}
```

A type is in `DynaSharp` if a user of `Table<T>` has to name it. A type only streams reach is in `DynaSharp.Streams`; a type table administration also uses stays in `DynaSharp.Requests`, so `Streams` depends on `Requests` and never the reverse, and nothing in `DynaSharp` names a type of `Streams` (`TableStreamExtensions` adds the stream readings of a `Table<T>` where the namespace is imported). `DescribeTableAsync` returns `TableDescription` of `Requests`, and `BatchIncompleteException` holds its `WriteRequest`.

Members that exist because generated code lives in the consumer's assembly are public, `[EditorBrowsable(Never)]` (so also out of the API reference), and infrastructure that changes with the package: `KeyWriter`, `KeyReader`, `KeyTimeFormat` (so `DynaSharp.Keys` shows no type), the members of `ConverterChecks` that generated code calls, `DynamoDbEntityInfo`, `DynamoDbIndexInfo`, `DynamoDbKeyTemplate`, `DynamoDbKeyInput`, `IKey`, and the structs of `DynaSharp.Expressions` with `ExpressionSink`, `ExpressionHandler`, `CommandHandle`. What a call site meets stays visible: `IKey<T>`, `ICondition` and the `IDynamoDb...<T>` interfaces are constraints, and `ConverterChecks.Expect` is for a converter of your own.

Three ways in, told apart by the shape of the call:

| | Request API | `Table<Item>` | `Table<Entity>` |
|---|---|---|---|
| Entry | `client.GetItemAsync(new GetItemRequest { ... })` | `client.Table("Shop", "pk", "sk")` | `shop.Of<Order>()`, `client.Table<Order>("Shop")` |
| Arguments | Request records | `AttributeValue` keys, `string` paths, `Item` | `Order.Keys.Of(...)`, `Order.Keys.Pk.Of(...)`, `Order.Attrs.X`, `Order` |
| Results | `XxxResponse` | `GetResult<Item>`, `WriteResult<Item>`, `Page<Item>` | The same over `Order` |
| Async type | `Task<T>` | `ValueTask<T>` | `ValueTask<T>` |
| A bad expression fails | At DynamoDB | At DynamoDB, with the rendered expression attached | At compile time for handles, at DynamoDB for raw paths |

`Table<T>` is the primary API. The request API is a sibling for administration, unmodeled parameters and migration, not a layer beneath it; both run on one pipeline with one telemetry. It follows the botocore service model in names and in what is required: a response record marks `required` only what the model does, and anything else is nullable or reads as its default, even members DynamoDB always sends (`TableDescription.TableName`, `CreateTableResponse.TableDescription`). An `Item` goes into any request (it is an `IReadOnlyDictionary<string, AttributeValue>`), and `ContinuationToken.ToKey()`/`FromKey(...)` bridge paging. An enum value of a response the library does not know reads as the zero member of its enum.

`TableDescription` holds the commonly needed subset. Its `SSEDescription` (`Status` as `SSEStatus`, `SSEType`, `KMSMasterKeyArn`, `InaccessibleEncryptionDateTime`) is `null` for the default key DynamoDB owns, for which DynamoDB sends none. `OnDemandThroughput` (`MaxReadRequestUnits`, `MaxWriteRequestUnits`, both `long?`) is one record for request and description: `CreateTableRequest`, `UpdateTableRequest`, `GlobalSecondaryIndex` and `UpdateGlobalSecondaryIndexAction` send it, `TableDescription` and `GlobalSecondaryIndexDescription` report it; `null` is not sent, and in a description means no maximum, as `-1` does. `UpdateGlobalSecondaryIndexAction.ProvisionedThroughput` is optional, as in the model, so an index of an on-demand table can take maximums alone. `UpdateTableRequest.SSESpecification` reuses the record of `CreateTable` and always sends `Enabled`, because `false` there switches back to the owned key, where `CreateTable` leaves the default out.

## 2. Client

```csharp
using var client = new DynamoDbClient(new DynamoDbClientOptions { Region = AwsRegion.FromName("eu-central-2") });
```

`DynamoDbClient` is sealed and `IDisposable`, with no interface: the test seam is the `HttpMessageHandler`. Members: `Options`, `Table(name, partitionKey, sortKey = null)`, `Table<T>(name)`, `Table<T>()`, `TransactWrite()`, `TransactGet()`, `ResolveTableName(declaredName)`, `DescribeTableAsync(tableName, ct)`, `DescribeTableAsync(tableName, timeout, ct)`, `SendRawAsync(operation, requestJson, ct)`, `Dispose()`. `DescribeTableAsync` returns the `DescribeTableResponse` of the request API without a request or `using DynaSharp.Requests;`. `new DynamoDbClient()` takes everything from the environment.

`Options`, on `DynamoDbClient` and `DynamoDbStreamsClient`, is what the client really uses, resolved once at construction: a region and an `AWS_ENDPOINT_URL` endpoint are filled in, `Credentials` is the provider in use. `client.Options with { MaxAttempts = 1 }` gives a second working client that shares the provider and a given handler; a handler the client made stays its own, so `HttpHandler` is null then. `ServiceUrl` holds an endpoint from the options or `AWS_ENDPOINT_URL` only: the public endpoint of the region and a service-specific variable (`AWS_ENDPOINT_URL_DYNAMODB`, `AWS_ENDPOINT_URL_DYNAMODB_STREAMS`) stay null although used, so that `Options with { Region = other }` goes to the new region's endpoint and a streams client built from a client's `Options` (and the reverse) reads its own endpoint. `ToString()` names the provider's type, shows no key, and an endpoint without user info.

| Option | Default | Note |
|---|---|---|
| `Region` | `AWS_REGION`, `AWS_DEFAULT_REGION`, the selected profile | Required, also with `ServiceUrl`: the signature contains it |
| `ServiceUrl` | `AWS_ENDPOINT_URL_DYNAMODB`, `AWS_ENDPOINT_URL`, the public endpoint | Absolute http or https, no user info, path, query or fragment |
| `Credentials` | The default chain | Not disposed by the client when given |
| `HttpHandler` | An owned pooled `SocketsHttpHandler` | Not disposed when given. Carries the requests to DynamoDB only: providers have their own HTTP client, so a stubbed client still calls the real STS or metadata endpoint when the environment selects that provider |
| `AttemptTimeout` | 30 s | Per attempt, credentials lookup included; surfaces as `TimeoutException` |
| `MaxAttempts` | 4 | Including the first; 1 means no retries. Full-jitter waits up to 100, 200, 400 ms for a transient failure (at most 700 ms, 350 on average) and up to 50, 100, 200 ms for throttling. Its remarks are the public description of the retry rules |
| `LoggerFactory` | None | |
| `TimeProvider` | `TimeProvider.System` | Timeouts, retry delays, batch backoff, signing time, waits for tables |
| `TokenSigner` | None: plain tokens | Signs and checks continuation tokens, section 6. `ToString()` names its type only |
| `TableNaming` | None | `Func<string, string?>` from the declared table to the one `Table<T>()` and `ResolveTableName` open, section 3; null or empty keeps the declared name; never applied to an explicit name. `ToString()` names its type only |

`DynamoDbClientOptions` is a sealed record (`options with { HttpHandler = stub, MaxAttempts = 1 }`). `DynamoDbClientOptions.ForEmulator(serviceUrl, region = "us-east-1")` gives `ServiceUrl`, the region and a `StaticCredentialsProvider` of `local`/`local`, the same on every call, because DynamoDB Local without `-sharedDb` keeps a database per access key and region. `ArgumentNullException` for null arguments, `ArgumentException` (`ParamName` `region`) for a name `AwsRegion.FromName` rejects; the client checks the URL as for `ServiceUrl`. A static factory, not a constructor or extension, so it reads as what it makes and the rest is a `with`.

## 3. Tables and indexes

```csharp
Table<Item> shop = client.Table("Shop", "pk", "sk");
Table<Order> orders = shop.Of<Order>();                       // the same table, key names from Order, cached per type
Table<Customer> customers = client.Table<Customer>("Shop");
Table<Cart> carts = client.Table<Cart>();                      // the table Cart declares, through TableNaming
Index<Order> byStatus = orders.Index(Order.Indexes.StatusIndex);
Index<Item> byStatusRaw = shop.Index("StatusIndex", "status", "placedAt");
Index<Item> byStatusMixed = shop.Index<Order>(Order.Indexes.StatusIndex);   // untyped, key names from the entity
```

`Table<T>` is sealed, immutable and thread-safe; `T` (`Item` or a generated type) decides only how items are written and read. `Name`, `PartitionKeyName`, `SortKeyName`, and `Client`, the client it was opened from, the same for every `Of<T>()` view and its indexes (`Index<T>.Table.Client`), so code that takes a table needs no client and reads clock and logger from `Client.Options`. `Of<T>()` and `client.Table<T>()` require an entity, not a document. Opening makes no request.

**The declared table.** `[DynamoDbEntity(Table = "...")]`, else `Table` of `[assembly: DynamoDbDefaults]`, sets the `init` property `DynamoDbEntityInfo.TableName` (null when neither says one). `client.Table<T>()` opens it after `TableNaming`, run on every call; without one it throws `InvalidOperationException` naming the entity and both fixes (`DYNA238` at compile time). `client.Table<T>(name)` opens the name as given, ARN included, untouched by declaration or `TableNaming`: the override, and what a test uses. `Of<T>()` keeps its table's name. `TableNaming` returning null or empty keeps the declared name; any other result is opened unchecked; its exceptions reach the caller. `client.ResolveTableName(declaredName)` is that step alone, for code that names a table without an entity (`ArgumentException` for null or empty). Every member that takes a table name (`Table(...)`, `Table<T>(name)`, `DescribeTableAsync(name)`, requests) takes the deployed name. A declared name follows DynamoDB's rules, 3 to 255 of `a-zA-Z0-9_.-` (`DYNA039`); two entities declaring one table with other key names are `DYNA040`. The declaration names the table, not an environment: `dev-` belongs in `TableNaming`.

**Names of table administration.** A member that sends one operation on the table is named after it, `Table` included: `Table<T>.CreateTable()` (a command, no `Async`), `DescribeTableAsync`, `DeleteTableAsync`, `client.DescribeTableAsync(name)`; the request API keeps botocore's names. The word stays because the table also receives item verbs: `orders.Delete(key)` deletes an item, `orders.DeleteTableAsync()` the table, and the names match the IAM actions `errors.md` lists. A member that sends no single operation says what it does: `WaitUntilActiveAsync` (polls `DescribeTable`) and the clauses of `CreateTableCommand`.

**Waits and timeouts.** `WaitUntilActiveAsync(ct)` (5 minutes) and `WaitUntilActiveAsync(timeout, ct)` return when the table and all its global indexes are `ACTIVE` (a table reads `ACTIVE` while an index backfills), and every global index the entities declare is listed (the entity of a `Table<T>`; on `CreateTableCommand` also those of `Including<T>`). DynamoDB allocates an added index before it backfills, which takes minutes on any table and often over five, so a wait after `UpdateTable` needs a longer timeout. On `CreateTableCommand` a declared index that is not listed ends the wait at the fifth look in a row (1.5 s), because a create lists all its indexes and only an `UpdateTable` sent before could add one; a look that lists all resets the count, one that finds no table does not count. `Table<T>` keeps polling, since an `UpdateTable` may still come. A table opened without an entity declares nothing; local indexes need no wait; there is no wait for one index. A wait that runs out throws `TableNotActiveException` (section 15). A response without a description gives one with the table's name and `TableStatus.Unknown`, which no wait takes for active.

`DescribeTableAsync(timeout, ct)`, on the table and the client, bounds one describe with its retries on the client's `TimeProvider`, the health check: a timeout above zero and at most 4294967294 ms, or `Timeout.InfiniteTimeSpan`, else `ArgumentOutOfRangeException` before a request. Running out throws `TimeoutException` naming the table with the inner `OperationCanceledException`; the caller's token wins with its own `OperationCanceledException`. A caller's token on the same timeout as a wait races it and gives a bare cancellation that names nothing. `CreateTableCommand` is in [Table administration and conflicts](#table-administration-and-conflicts).

**Keys of a table of an entity.** A `Table<T>`/`Index<T>` of an entity takes only generated keys: `IKey<T>` (`T.Keys.Of(...)`, or the entity for `Get` and `Delete`), `PartitionKey<T>` (`T.Keys.Pk.Of(...)`, an index's builder) and sort key conditions. Stored key values (`AttributeValue`, strings, lists of them) go with `Item` only: `Get`, `Update`, `Delete` and the four `Query` forms that take them are extensions of `ItemTableExtensions` on `Table<Item>`/`Index<Item>`, as are `Get(...)` of `BatchGetCommand<Item>` and `Delete(...)` of `BatchWriteCommand<Item>`; transaction verbs and batch `Delete(table, ...)` take them with a `Table<Item>`. On an entity such a key would skip its template (`customers.Get("1")` asks for `1`, the item is `CUSTOMER#1`), so it does not compile (`DYNA230` explains). An index keyed by the discriminator has `QueryByDiscriminator(sortKey)` on `Index<T>`; a hand-written entity implements `IKey<T>` or passes `new PartitionKey<T>(value)`.

`Index<T>` has `Query` and `Scan` only, so writes through an index do not compile. `orders.Index(name)` and `shop.Index<Order>(name)` throw `ArgumentException` for an index the entity does not declare (`DYNA207` for a constant).

## 4. Generated surface

For `[DynamoDbEntity]` and `[DynamoDbDocument]` types, which must be `partial`:

| Member | Content |
|---|---|
| `T.Keys.Of(...)` | `readonly struct PrimaryKey : IKey<T>` over the placeholder values, which renders no string until written. Checks the values at the call like `Format`, so `Keys.Of("a#b")` throws `KeyFormatException`; `T.Keys.TryOf(...)` returns `null` instead. A key of another entity does not compile |
| `T.Keys.Pk`, `Sk`, `Gsi1Pk`, ... | One static class per key. A template has `Format`, `Parse`, `TryParse`; a partition key (table or index) `Of` and `TryOf` with `Format`'s parameters; a sort key `Prefix`, `UpperBound`, `BeginsWith` at every depth, `PrefixPartial` when the last placeholder is a string, and the conditions of section 6. A plain key, or a template of one bare placeholder over its property's attribute, has `Of(value)` with the property's type and converter (a `PartitionKey<T>` on a partition key, the `AttributeValue` for a `SortKeyCondition` on a sort key), `Format(value)` when stored as a string, nothing to parse, no prefix, and on a sort key the conditions that fit what it stores |
| `T.Attrs.X` | A handle `Attr<TValue, TConverter>` per stored attribute, documents included. `TValue` is the type without `?`; nullability is in the converter: `Attr<int, NullableHandleConverter<int, NumberConverter<int>>>`, `Attr<string, NullableReferenceHandleConverter<string, StringConverter>>`. `internal` unless property, type and converters are public. None for an attribute name with `.` or `[`, or a `[KeyOnly]` property |
| `T.Indexes.X` | A `const string` per index: `orders-by_date` gives `OrdersByDate`, `GSI1` gives `Gsi1` |
| `T.TableName` | A `const string` of the declared table as written, on an entity that declares one (own or assembly default); `new` where a base type has the name. The opened name is `client.Table<T>().Name` |
| `DynamoDbEntities.IncludingAll()` | Once per assembly, `internal`, namespace `DynaSharp`: an extension of `CreateTableCommand` that is `Including<T>()` of every entity in ordinal order of full names. Only when all entities have the same key names and none is nested in a type that hides it; otherwise none, and `DYNA037` (info) says why. Internal, so no clash across assemblies; one that sees the internals through `InternalsVisibleTo` and has its own gets CS0121 and names the entities. A type named `DynaSharp.DynamoDbEntities` is `DYNA038`. Generated code, no runtime API |

`Order.Keys.Pk.Of(userId)` returns `PartitionKey<Order>`, a readonly struct over the stored key, one type for every key builder of an entity. A template or plain string costs what `Format` costs; a plain number or binary goes through its converter once. No implicit conversion to `AttributeValue` (it would bring back the mistake it rules out); `.Value` is the explicit way out, and its text is the digits of a number or the base64 of binary. `BeginsWith()` and `BeginsWith(leading...)` return a `SortKeyCondition`.

**`TryOf`** is for a value from outside: `null` exactly where `Of` throws `KeyFormatException`, because both run one generated code path over one `KeyWriter` told not to throw; nothing is thrown and caught, and it costs what `Of` costs. It returns `PrimaryKey?`/`PartitionKey<T>?` (`is { } key`), no `out` form. Sort key builders have none (no `Of`). It exists only where a value can be turned away: not on a key of literals, a plain key (no template; an empty string is DynamoDB's to reject), or a key of `Guid`, `DateOnly` and `DateTimeOffset` alone; `Keys.TryOf` checks the keys that can fail. The rule is by encoding: a plain number counts, as does `d3` over a `byte`.

The check of `Keys.Of` renders into a stack buffer (a longer value borrows from the pool, as a write does) and drops it; a command renders again when it writes. A key that cannot fail skips it. `default(PrimaryKey)` throws when written.

A timestamp in a template is UTC, and bare `{At}` is `{At:ticks}`: `2026-10-09T10:00:00.1234567Z`, the only lossless format, so a read can restore the property from the key. `{At:ms}` stores `2026-10-09T10:00:00.123Z`, what AWS SDK keys hold. Other formats are in `requirements.md`.

**`raw`.** A value holding its template's delimiter throws `KeyFormatException`, unless the placeholder is `raw`: `[PartitionKey("appointment#{Key:raw}", AttributeName = "Id")]` over `[KeyOnly] public required string Key` gives `Format("a#b")` = `appointment#a#b`, and `Parse` gives `a#b`. `[KeyOnly]` belongs with it because a `Put` stores a template input as its own attribute and an `Update` does not, so without it items differ by writer (`DYNA123`); on a table whose items hold the attribute, a `Put` drops it. `raw` goes on a `string` placeholder that ends the template (`DYNA118`, `DYNA104`). Only the delimiter check goes: empty, ill-formed text, control characters and U+10FFFF still throw, on writes and through `Keys.Of`, and `Parse` refuses them, so such a stored key gives `DynamoDbMappingException` on a read that restores an input from it, and a multi-item read ends there unless `OnMappingFailure` skips it. `Keys.TryOf` answers for the table key only: with a strict index it returns a key and the `Put` throws. A plain key suits entities with keys of several shapes and values that must miss rather than throw. `Format`, `Parse`, `TryParse`, `PrefixPartial`, `Eq`, the ranges and restoring reads work as for a string that ends the key. A value without a delimiter gives the same bytes with or without `raw`, so toggling it moves no stored key. The format is per template: a `{Key}` of the same property in an index still rejects what `{Key:raw}` takes.

`Keys`, `Attrs` and `Indexes` are reserved member names on every mapped type, `TableName` on an entity that declares a table (`DYNA014`). A type named like a member generated into it is `DYNA025`; a simple name in the type that a generated member would capture from outside is `DYNA043`. A string before a delimiter in a sort key is `DYNA115` at `Info`: the ordering caveat is real but rare, and a warning would fail warnings-as-errors builds on hierarchical keys.

|---|---|---|
| `[DynamoDbEntity]`, `[DynamoDbDocument]` | type | A type with keys, a nested type without. `Table` declares the entity's table, section 3 |

| `[DynamoDbConverter(type)]` | property, type | First in converter selection, property before type |
| `[DynamoDbConstructor]` | constructor | The constructor reads use |

Default `Throw`. Writes unchanged. Elements of collections and plain keys still throw. `DYNA033` on the attribute for a `[Flags]` enum (a number) or one with its own converter; on the property where an unknown name throws anyway (`required` non-nullable, a constructor parameter without default, a plain key) |
| `[assembly: DynamoDbDefaults(...)]` | assembly | `Naming`, `DiscriminatorOptOut`, `OmitEmpty`, `Table`, below |
| `[assembly: DynamoDbDefaultConverter(type, converter)]` | assembly | One per type, third in converter selection (after property and type `[DynamoDbConverter]`, before built-ins) |

A base type's property maps as it does there. An override inherits the overridden property's attributes, and one of the same kind on the override wins. A base property whose setter the derived type cannot reach (`private set`) is not stored: `DYNA034`.

The default names are frozen: `pk`, `sk`, `<index>pk` and `<index>sk` (index name lower-cased), `_type`. They are in the data of every table a default wrote, so a new default would orphan those items silently; `AttributeName` is the only way to another name.

Assembly defaults hold for the assembly's types, nested ones too; an analyzer meeting a type from metadata reads that type's assembly.

```csharp
[assembly: DynamoDbDefaults(Naming = AttributeNaming.CamelCase, DiscriminatorOptOut = true, OmitEmpty = true)]
[assembly: DynamoDbDefaultConverter(typeof(DateTimeOffset), typeof(StoredTimestampConverter))]
```

| Default | Meaning |
|---|---|
| `Naming` | `AsDeclared` (default), `CamelCase`, `SnakeCase`, by `JsonNamingPolicy.CamelCase`/`SnakeCaseLower`, for every attribute derived from a property. `[DynamoDbAttribute]` and `AttributeName` win. Collisions are `DYNA004` |
| `DiscriminatorOptOut` | An entity without `[Discriminator]` behaves as `OptOut = true`, no `DYNA020`. `[Discriminator("X")]` still wins |
| `OmitEmpty` | Every property `[OmitEmpty]` fits behaves as marked, except key inputs and what a read needs, which stay written silently. `[OmitEmpty(false)]` takes it back |
| `Table` | The table of every entity that declares none. The entity's own wins; an invalid name is `DYNA039` once, on the assembly attribute |

`Naming` does not touch the frozen names. A plain key derives from its property (`[PartitionKey] public string UserId` is `user_id` under `SnakeCase`), so a table with another key takes `AttributeName`, because DynamoDB cannot rename a key; a template of one bare placeholder is its property's attribute only if its `AttributeName` is the converted name. Changing `Naming`, or renaming a property under any naming, renames stored attributes: old items read as missing, an error only for `required`. A property whose name may change takes `[DynamoDbAttribute]`.

**Converter selection.** A default converter applies, after property and type attributes, to the type, its nullable form and elements of lists, dictionaries and arrays; a set element needs an `IDynamoDbSetElementConverter<T>`, else `DYNA003`. In a key it acts as `[DynamoDbConverter]` on the property: a plain key goes through it and takes any type (no `DYNA017`), a template placeholder keeps its format (a type without one is `DYNA103`). A `[Version]` keeps the built-in converter, because an update adds to it. A misfit converter is `DYNA008`; two defaults for one type, a nullable type or an open generic are `DYNA029`. TTL is `[DynamoDbConverter(typeof(EpochSecondsConverter))]` on a `DateTimeOffset` with `[TimeToLive]`.

Opt-in converters for what other writers stored. None is a default, because defaults are frozen with the data they wrote:

| Converter | Of | Stores | Reads |
|---|---|---|---|
| `EpochSecondsConverter` | `DateTimeOffset` | `{"N":"1793448000"}`, whole UTC seconds | Whole seconds in range, offset zero |
| `SetArrayConverter<T, TElement>` | `T[]` | The set `TElement` says | That set, empty for none |
| `BoolAsNumberConverter` | `bool` | `{"N":"1"}`/`{"N":"0"}`, AWS SDK conversion V1 | Zero `false`, other numbers `true`; `BOOL` throws |
| `SdkDateTimeConverter` | `DateTime` | `{"S":"2026-10-31T12:00:00.123Z"}`, UTC, three digits, `Unspecified` as local (SDK 4, V1 and V2) | What `DateTimeConverter` reads, as `Utc` (SDK 4 with `RetrieveDateTimeInUtc`) |
| `OffsetTimestampConverter` | `DateTimeOffset` | `{"S":"2026-11-20T11:00:00.0000000+01:00"}`, `"O"` with offset | `DateTimeOffsetConverter`'s forms, keeping the offset, `Z` as zero |
| `EmptyStringAsMissingConverter<T, TConverter>` | any | What `TConverter` writes | What `TConverter` reads, plus `CountsAsMissing` for `{"S":""}`. Passes `IsOmitted` on, not `TryReadMissing`, so `DYNA209` still sees a throwing `Select` |

The generator knows two by name because plain keys depend on them: `BoolAsNumberConverter` makes a number key, `SdkDateTimeConverter` a plain sort key with ranges.

**Write failures.** A built-in converter refusing a value (`DateTimeConverter` on `DateTimeKind.Unspecified`, number converters on NaN or infinity) throws `ArgumentException`/`ArgumentOutOfRangeException`. An empty set property is left out, which an element cannot be, so a set inside a list or dictionary goes through `NonEmptySetConverter`, which throws `ArgumentException`; the set converters themselves write an empty set as given, so `Set(Attrs.Tags, [])` is sent and DynamoDB rejects it. The generated write of a property wraps such exceptions (exception filter, same type, the converter's as inner, nothing on the success path) in a message naming property, type, attribute, the problem and the fix, never the value: `The property LoggedAt of Logbook, the attribute "logged_at", cannot be written: its DateTime has DateTimeKind.Unspecified, ...`. A key template reports such a `DateTime` with `KeyFormatException` naming the template; a write by handle throws what the converter throws.

**Reads.** Generated code reads JSON into the type with no `Item` between. A typed read checks `_type` when present and throws `DynamoDbMappingException` naming the type found. Unknown attributes are skipped. A missing attribute leaves the property at its initial value (initializer or constructor default; null for a nullable one without either). A missing `required` member throws, unless nullable, because null is omitted on write; so a nullable property with a non-null initial value reads a written null back as that value (`DYNA035`, warning). A missing non-nullable set reads as empty. A key input whose attribute is missing is restored from its key when the format is lossless (what an `Update`-created item looks like).

**Custom converters** implement `IDynamoDbConverter<T>` with static abstract members on a struct or class (so a generic converter is `CA1000` where that is an error; the way out is one struct per type over a helper). A number or set converter implements `IAddableConverter` to allow a typed `Add`. A set converter answers `TryReadMissing` with an empty set, because DynamoDB has no empty set and `Select` throws otherwise; that member stays visible for this case.

`CountsAsMissing(in DynamoDbReader reader, AttributeType type)` says a stored value counts as absent: the read-side mirror of `IsOmitted`, for lenient enums or blank-as-null. `Read` stays strict (lists have positions), so such a converter looks twice, only on properties whose converter answers; the default answers false and other properties' reads hold no question. `[DynamoDbConverter]` and `[DynamoDbDefaultConverter]` work alike; `[OmitEmpty]` passes the question on and has no answer (a stored `""` reads as `""`); the generated enum converter with `CountsAsMissing` answers, and its handle's forwarder passes it on, so `Select` asks too. Absent means what a read does for a missing attribute (above; `required` throws, a key input is restored). `{"NULL":true}` on a nullable property reads null without asking. Not asked: collection elements, plain keys (whose initial value would be another item), `Keys.X.Parse`, `Item`. A read asks before it skips or reads, so the converter consumes nothing: the reader comes by `in`, calls that move it move a compiler copy, and `ref` passing or assignment does not compile; to look inside a list or map it copies once (`var map = reader;`, under 200 bytes of stack).

## 5. Commands

Every method of a table that reads or writes items starts a command, a `readonly ref struct` over pooled state. `CreateTable()` starts an ordinary class, `CreateTableCommand` (administration is no hot path), which has no `MaxAttempts`. A command is built and sent in one expression; `diagnostics.md` lists what the compiler refuses. Every fluent call uses up its handle and returns a new one, so a second use throws `InvalidOperationException` (`DYNA204` where visible), and a dropped result sends nothing (`DYNA203`). The method that returns a command is the template of a request, and a helper takes and returns one:

```csharp
public static UpdateCommand<T> Audited<T>(this UpdateCommand<T> command, string user)
    where T : IDynamoDbDocument<T> => command.Set("updatedBy", user);

public static TCommand OwnedBy<TCommand>(this TCommand command, string owner)
    where TCommand : IConditional<TCommand>, allows ref struct => command.If(Attr("owner").Eq(owner));
```

| `IFilterable<TSelf>` | Query, Scan, fan-out and mixed reads | `Filter` |

| `ITransactWriteChain<TSelf>`, `ITransactWriteStep<TSelf>` | `TransactWriteCommand` and the steps | Carry the verbs of section 11; nothing outside the library implements them |

Their type parameter `allows ref struct`, so a generic helper does not box. A condition to keep in a field is a `Condition`, section 9.

Every async terminal takes a `CancellationToken`. `await command` is `SendAsync()` where there is one; the awaiter is hidden and takes no token. A read has no default terminal (`DYNA202`), so `await shop.Query(pk)` does not compile. `ToRequestJson()` ends the command, sends nothing and renders the body with everything enforced; on a batch it renders the first request; a parallel scan has none (one request per segment). `CreateTableCommand.ToRequestJson()` renders the body of `ToRequest()`, does not end the command, and leaves out `IfNotExists`, `WaitUntilActive` and `TimeToLive`. ## 6. Reads

```csharp
GetResult<Item> got = await shop.Get("USER#alice", "PROFILE").Consistent().Project("fullName", "city").SendAsync(ct);
Customer? alice = await customers.Get(Customer.Keys.Of("alice")).ItemAsync(ct);
Customer? reloaded = await customers.Get(alice!).ItemAsync(ct);    // key from the entity

await foreach (Order order in orders

{

Page<Order> page = await orders.Query(pk).Limit(25).PageAsync(ContinuationToken.Parse(fromClient), ct);    // null on the first page
string? next = page.HasMore ? page.Next.ToString() : null;

Order? open = await orders.Query(pk).Filter(Order.Attrs.Status.Eq(OrderStatus.Open)).ItemAsync(ct);    // the first match, or null
Order? newest = await orders.Query(pk).Descending().Limit(1).ItemAsync(ct);                            // a read without a filter says one is enough
Order? held = await orders.Query(Order.Keys.Of("alice", "o1")).ItemAsync(ct);                          // takes what Get takes

await foreach (Order order in byStatus.Query(Order.Keys.StatusIndexPk.Of(OrderStatus.Open), Order.Keys.StatusIndexSk.Ge(from)).ItemsAsync(ct)) { }
Page<Item> segment = await shop.Scan().Segment(2, of: 8).PageAsync(after, ct);
await foreach (Item item in shop.Scan().Parallel(segments: 8).ItemsAsync(ct)) { }
```

**Partition keys.** `Query` on `Table<T>`/`Index<T>` takes a `PartitionKey<T>`, so another entity's key does not compile; a table's and its index's partition keys share the type, so a key remembers the attribute it was built for, and `Query` throws `ArgumentException` naming the builder to use when it is not the attribute read (DynamoDB would return nothing silently). The message names `QueryByDiscriminator()` for the discriminator, the index declaration on an entity, the attribute's value on `Item`. An index on the table's attribute (local ones included), and a fan-out, take the table's key; an overloaded index takes every entity's key on it. `Table<Item>`/`Index<Item>` take a `PartitionKey<TEntity>` of any entity (`shop.Query(Order.Keys.Pk.Of(id)).Of<Customer, Order>()`). The extension classes say what they take: `ItemTableExtensions` key values and attribute names, on `Table<Item>`, `Index<Item>`, `PutCommand<Item>` (`Put()`, `With`) and `Item` batches; `EntityTableExtensions` what an entity builds (`PartitionKey<T>`, the entity for `Get`/`Delete`, an index by declared name); `EntityWriteExtensions` the write-rule clauses `IfVersion`, `IgnoreVersion`, `StoreKeyInputs`. `Query` by `PartitionKey<T>` is an extension so it applies only where no member does: no call that compiled before can rebind.

`Query<TKey>(key)` on `Table<T>` takes what `Get` takes and queries the partition with `Eq` on the sort key. A member that fails its constraint is no candidate, so a `PartitionKey<T>` binds to the extension, and on `Table<Item>` a string binds to the key-value form. `ItemAsync` (table and index) gives the first matching item in query order or null, follows empty filtered pages and stops at the first item. It adds no `Limit`, since `Limit` works before the filter and the request stays what `ToRequestJson()` shows; an unfiltered read asks `.Limit(1)` itself. Fan-out, mixed reads and scans have no `ItemAsync`.

### Sort key conditions

```csharp
invoices.Query(pk, Invoice.Keys.Sk.Between(from, to));        // [SortKey("INVOICE#{IssuedAt}#{Id}")]: from the first key at from to the last at to
invoices.Query(pk, Invoice.Keys.Sk.Range(from, to));          // [from, to)
invoices.Query(pk, Invoice.Keys.Sk.Ge(from));                 // from then on, and what else sorts after that
invoices.Query(pk, Invoice.Keys.Sk.Eq(issuedAt, id));         // that one key
stock.Query(pk, Stock.Keys.Sk.Between("books", 10, 99));      // [SortKey("{Shelf}#{Row:d3}#{Id}")]: rows of one shelf
```

The builder writes conditions from placeholder values, so nobody combines `Prefix` and `UpperBound` by hand; `SortKeyCondition` stays for a value already at hand. Arguments are the leading placeholders as `Prefix` takes them, at every depth with a value; a key ending in a placeholder has that full depth too.

| Generated | Key condition | Key ending in a placeholder, at full depth |
|---|---|---|
| `Eq(all placeholders)` | `= Format(...)` | The same |
| `Between(leading..., from, to)` | `BETWEEN Prefix(leading..., from) AND UpperBound(leading..., to)` | `BETWEEN Format(leading..., from) AND Format(leading..., to)` |
| `Range(leading..., from, to)` | `BETWEEN Prefix(leading..., from) AND Prefix(leading..., to)` | None |
| `Ge(x...)` | `>= Prefix(x...)` | `>= Format(x...)` |
| `Gt(x...)` | `> UpperBound(x...)` | `> Format(x...)` |
| `Le(x...)` | `<= UpperBound(x...)` | `<= Format(x...)` |
| `Lt(x...)` | `< Prefix(x...)` | `< Format(x...)` |

Bounds are whole fields; a field a bucket format truncates compares as its bucket (`Gt` of a day leaves out the whole day). A key ending in a placeholder has no prefix there (no delimiter ends the last field), so the complete key is both bounds; an upper bound would be wrong for a string (`Gt("a")` must keep `ab`). `Between("a", "m")` takes whole values, so `ma` stays out, unlike `PrefixPartial`. Invalid values throw `KeyFormatException`; `from` above `to` is DynamoDB's `ValidationException`.

`Between` varies the last placeholder and keeps the earlier ones equal, the one range that holds for every template; both ends inclusive, so on a key that continues past the field it includes all of `to`. `Range` is `[from, to)`: `BETWEEN` includes its bound, but every stored key at `to` continues past the prefix and sorts above it, and no key is the prefix itself since no value is empty. So a `Range` of a bucket stops before the whole bucket and `Range(to, to)` reads nothing. A range across whole tuples is written by hand from `Prefix`/`UpperBound`. `Ge`, `Gt`, `Le`, `Lt` take a tuple, compare in key order and have one open end, so they run past the template: `Ge(at)` also reaches `PROFILE` above `INVOICE#`, which a typed read filters away after reading and `Table<Item>` returns.

What cannot be correct is not generated:

- No range without a value: `Ge()` of a bare prefix asks for what lies outside the template. `BeginsWith()` reads all of it; a template of literals has `Eq()`.
- No range ends on a field whose bytes do not follow its value: plain digits (`10` before `9`), a plain decimal, an enum by name, a custom type.
- No `Range` where nothing follows the field (a bound would be a key `BETWEEN` takes): not where the key ends in the placeholder, not in `{Day:d3}#` (the day's prefix is the whole key), yes in `{Day:d3}#end`; and none where `Between` is not, so none on a plain key.
- A string is in order at the end of the key and before a space; before any other delimiter `a b` sorts below `a` (`DYNA115`), so no range ends on such a field and no open range passes one: `{Shelf}#{Row:d3}#{Id}` has `Between(shelf, from, to)` but no `Ge(shelf, row)` and no range of shelves. A raw value ends the key, so it is in order.

A plain sort key compares as stored, so each condition is `SortKeyCondition` over `Of`. Number, binary, `string`, `Guid`, `DateTimeOffset`, `DateTime`, `DateOnly`, `TimeOnly`, `SdkDateTimeConverter` (fixed width) and `BoolAsNumberConverter` have `Eq`, `Between`, `Ge`, `Gt`, `Le`, `Lt`; `TimeSpan`, enums, `OffsetTimestampConverter` (does not sort across offsets) and custom converters `Eq` alone; a `string` also `BeginsWith(prefix)`.

A version-7 `Guid` starts with its millisecond time, and its stored lowercase text sorts by it. `Guid.FirstVersion7(at)`/`Guid.LastVersion7(at)` (static extension members of `GuidExtensions`) are the lowest and highest v7 value of that millisecond (`…-7000-8000-000000000000`, `…-7fff-bfff-ffffffffffff`), so every `Guid.CreateVersion7(at)` lies between them and `LastVersion7` sorts below the next millisecond: `Between(Guid.FirstVersion7(from), Guid.LastVersion7(to))` takes both milliseconds whole, `Lt(Guid.FirstVersion7(to))` stops before `to`. Sub-millisecond parts and the offset are dropped and pre-epoch instants throw `ArgumentOutOfRangeException`, as in `Guid.CreateVersion7`. No time-ordered id type: a ULID is a `string` and sorts the same way. A condition of constant text or a plain string allocates nothing; one that formats a value costs its strings.

**Paging.** `ItemsAsync` and `PagesAsync` follow pages, empty filtered ones included, and enumerate once. `PageAsync`'s position is a `ContinuationToken?`: null or `default` is the first page. `PageAsync(ct)` is the first page without a `null` in front (a `CancellationToken` does not convert to the position; its token has no default, so `PageAsync()` stays the positional overload). `Page<T>` has `Items`, `Count`, `ScannedCount`, `ConsumedCapacity`, `HasMore` and `Next`, a plain token (`Next.HasValue` is `HasMore`). `ItemsAsync` drops capacity; a caller who wants it pages. `SortKeyCondition` offers only the operators a key condition allows: `Eq`, `Lt`, `Le`, `Gt`, `Ge`, `Between`, `BeginsWith`. `CountAsync` is `Select: COUNT` summed over pages and throws `InvalidOperationException` with a projection. `Parallel(segments)` returns `ParallelScanCommand<T>` with `ItemsAsync` only (a merged page has no single key); concurrency is the segment count, and paging goes through `Segment(n, of: m)`.

A typed `Query`/`Scan` of an entity with a discriminator filters `#_type = :t` (visible in `ToRequestJson()`), which costs no capacity beyond the read, so `ScannedCount` can exceed `Count`. On a table or index keyed by the discriminator the key condition does it, as DynamoDB refuses a filter on a key.

### Items that do not fit

```csharp
var unreadable = new List<Item?>();
await foreach (Order order in orders.Query(pk).OnMappingFailure(failure => unreadable.Add(failure.Key)).ItemsAsync(ct)) { }
```

An item the type cannot read ends the read with `DynamoDbMappingException` by default: it is a bug of the model or a writer, and dropping it would hide that. `OnMappingFailure(Action<DynamoDbMappingException>)` on `QueryCommand<T>`, `ScanCommand<T>`, `FanOutQueryCommand<T>` and the mixed commands (and `onMappingFailure` of `ReadChangesAsync`, section 15) skips it and hands the exception to the callback, with `EntityType`, `AttributeName` and `Key` (the table's key attributes as stored, also on an index). A callback, not a result type, because a result type would change the element type of every terminal and the exception already identifies the item. Nothing logs it; `OnMappingFailure(static _ => { })` skips and counts only. A second call replaces the first. It covers `ItemsAsync`, `ItemAsync`, `PageAsync`, `PagesAsync`, and the terminals of a `Select` after it (no key in that response, so `Key` is null). A `Parallel` scan takes it from the scan before.

Only `DynamoDbMappingException` is skipped: an item of another type no filter kept out, an unreadable value, a missing `required` attribute, a stored key that does not fit its template, and on a fan-out an item without the keys the merge orders by. A page without a failure pays nothing; a read without the clause costs one null check per page.

The callback runs once per skipped item, after its page's call and before that page's items are given out. It runs outside the call, so what it throws is neither a parse failure nor retried: it ends the read. Parallel scans and fan-outs can run it concurrently. Each skipped item counts in `dynasharp.client.operation.skipped_items` (`{item}`; `db.operation.name`, `db.collection.name`, `server.address`) after the callback returns.

A skipped item is not in `Page<T>.Items`, while `Count` stays DynamoDB's (so `Count - Items.Count` is what a page skipped; a fan-out page counts what it gives, so there it is in neither). `Limit` counts it, so a page can hold fewer items. `Take(n)` reads on, `ItemAsync` gives the first readable item, `CountAsync` counts it. `Next` is past it, so it is not read again; a fan-out continues after the last item it gave per partition, so a skipped item behind that comes again on the next page, callback included.

### One attribute

```csharp
SelectResult<decimal> total = await orders.Get(key).Consistent().Select(Order.Attrs.Total).SendAsync(ct);
decimal value = total.Found ? total.Value : 0m;                                                  // no item is no error
decimal orZero = total.GetValueOrDefault(0m);
SelectResult<string?> email = await customers.Get(Customer.Keys.Of("alice")).Select(Customer.Attrs.Email);    // null for an item without it

await foreach (decimal amount in orders.Query(pk).Filter(Order.Attrs.Status.Eq(OrderStatus.Open)).Select(Order.Attrs.Total).ValuesAsync(ct)) { }
SelectResult<decimal> newest = await orders.Query(pk).Descending().Limit(1).Select(Order.Attrs.Total).ValueAsync(ct);
Page<decimal> totals = await orders.Scan().Select(Order.Attrs.Total).PageAsync(after, ct);
```

`Select(handle)` on `GetCommand<T>`, `QueryCommand<T>` and `ScanCommand<T>` projects one attribute and reads its value without the entity, so `required` members are not in the way (the difference to `Project`). It saves bandwidth, not capacity. It ends the chain: the commands it returns have terminals only, so `Project` or a second `Select` after it do not compile, and every clause comes before it; that is a smaller surface than repeating eight clauses on three types. A `Project` before it throws `InvalidOperationException`. Not on fan-out, mixed reads or `BatchGet`; more than one handle is a later step.

The value follows the handle: `TValue` is the property's type (`Order.Attrs.Total` gives `decimal`, `Customer.Attrs.Email` a `string?`). A missing attribute gives null on a nullable handle, an empty set for a set, and otherwise throws `DynamoDbMappingException`, never a default: a read of the entity would give an `int` its initial value, `Select` throws. A `[Version]` does the same, with a message that the item has no version and a pointer to `VersionMissing.Allow`; `DYNA209` does not report it, because every write stores the version except an `Update` with `IgnoreVersion()` that creates the item. With `VersionMissing.Allow` it gives 0 (section 8). No item is `Found == false`. A stored `{"NULL":true}` is null on a nullable handle and throws on another; an unreadable value throws, naming the attribute. A value the converter counts as missing reads as missing (null on a nullable handle even where the entity read keeps an initializer, else the converter's `TryReadMissing`, else a throw `DYNA209` reports). `Return(attr)` throws for it as for a missing attribute.

`SelectResult<TValue>` is what `SendAsync` of a get and `ValueAsync` of a query give: `Found` (an item exists) and `Value`, the shape of `GetResult<T>` but for one word, since `GetResult<T>.Found` means `Item` is not null, which an attribute cannot promise. `Value` throws `InvalidOperationException` for no item (a 0 would read like one); `GetValueOrDefault()` and `GetValueOrDefault(defaultValue)` are `Nullable<T>`'s names for the non-throwing form. A found item whose nullable attribute is null gives null, not the fallback. `DYNA227` (Info) reports `Value` in a member that reads no `Found` of any `SelectResult`, by member and not flow. A scan has no `ValueAsync`.

On a table of several entities `ToRequestJson()` shows the behaviour: a `Get` projects the discriminator beside the attribute and an item of another type throws as `orders.Get(key).ItemAsync()` does; `Query`/`Scan` keep their discriminator filter and bring back the attribute alone; a query keyed by the discriminator projects it and checks each item. Without a key in the response, `DynamoDbMappingException.Key` is null.

The handle reads through the property's converter with `[DynamoDbConverter]` and `[OmitEmpty]` as they are: a stored `""` reads as `""`, an omitted attribute as missing. A nested path `Order.Attrs.ShipTo.At(Address.Attrs.City)` reads through maps, and its last handle decides (a non-nullable `City` throws for an item without `ShipTo`, even if `ShipTo` is nullable). A path with a list index throws `ArgumentException`, because DynamoDB returns a shortened list. A `[KeyOnly]` property has no handle. A stored input of a table key has one, but an `Update`-created item holds only the key: the entity read restores the input, `Select` throws (`DYNA209`), since that would need the template's parser at run time for a value the caller holds anyway; `StoreKeyInputs()` stores it.

**Continuation tokens.** `ContinuationToken` is a position: `default` (or null `after`) is the start; `Parse`/`TryParse` take what `ToString()` gave, and null or `""` give `default`. The text is URL-safe and encoded, not signed or encrypted: it carries the key values of the last item, as `LastEvaluatedKey` does. It starts with its format version (pages and fan-out alike), so `Parse` rejects another format, older or newer, with a `FormatException` that quotes nothing and asks to restart the read; `TryParse` is false. No length limit: a page token is as long as a key, a fan-out's grows with its partitions. `ToKey()`/`FromKey(key)` convert to and from a key of the request API. Two tokens are equal if their text is.

**Signed tokens** are opt-in, for a web API whose clients must not choose their position: `TokenSigner = new ContinuationTokenSigner(current, previous)`. A key has at least `MinKeyLength` (32) bytes and is copied; the first key signs, every key is tried to check (`CryptographicOperations.FixedTimeEquals`), which is how keys rotate. The signer is per client, not per call or table, so all reads of a client sign, instances sharing keys accept each other's tokens, and a client without one keeps plain tokens.

| | |
|---|---|
| Format | Version 2: `Base64Url([2][key JSON][HMAC-SHA256, 32 bytes])`. Version 1 stays `[1][key JSON]` |
| Signed message | `[2][key JSON][length of the key, 4 bytes big-endian]DynaSharp.ContinuationToken\0{"TableName":"…"[,"IndexName":"…"]\0<key condition>[\0<partitions>]` |
| Bound | Table, index, the key condition with names and values in place of placeholders (`#"pk" = :{"S":"a"} AND begins_with(#"sk", :{"S":"x"})`), and for a fan-out the partition keys. A scan binds table and index |
| Not bound | Filter, projection, `Limit`, direction, consistency (a fan-out still checks its direction). No expiry |
| Checked | In `PageAsync` of `Query`, `Scan`, their `Select` and mixed forms, and the fan-out, before a request. `Parse` checks only the shape (it has no keys) |
| Rejected | With a signer: a signature that does not hold (altered, made up, another query, a retired key) and a plain token from `Parse`/`TryParse`. Without a signer: a signed token. All `FormatException`, quoting nothing, asking to restart |
| Accepted unsigned | A plain token this process made (`FromKey`, or kept from a client without a signer), since it is no client input |

A patch release reads and writes the token formats of the release before; a format change gets a new version and a release note (`docs/compatibility.md` covers rolling deployments). Within the key condition a chosen position is only a place among items the caller may read anyway (DynamoDB rejects a start key outside it, and filters apply from any position), so signing matters where the key condition is not what separates callers.

## 7. Writes

```csharp
await shop.Put(new Item { ["pk"] = "USER#alice", ["sk"] = "PROFILE", ["fullName"] = "Alice" }).SendAsync(ct);
await shop.Put().With("pk", "USER#alice").With("sk", "PROFILE").IfNotExists().SendAsync(ct);    // Table<Item> only
WriteResult<Customer> replaced = await customers.Put(customer).ReturnOld().SendAsync(ct);

await shop.Update("USER#alice", "PROFILE")
    .Set("city", "Bern")
    .Add("orderCount", 1)
    .Remove("legacyFlag")
    .If(Attr("version").Eq(3))
    .SendAsync(ct);

int count = await customers.Update(Customer.Keys.Of("alice"))
    .Add(Customer.Attrs.OrderCount, 1)
    .MaxAttempts(1)
    .Return(Customer.Attrs.OrderCount)
    .SendAsync(ct);

await shop.Delete("USER#alice", "PROFILE").If(Attr("orderCount").Eq(0)).SendAsync(ct);
await customers.Delete(customer).SendAsync(ct);    // key from the entity
```

`Put` replaces the whole item; `Update` is an upsert unless `IfExists()`. `Put()` without an item and `With` exist on `Table<Item>` only, so a typed put goes through the entity. Conditions accumulate with `AND`. `IfNotExists()`/`IfExists()` are `attribute_not_exists`/`attribute_exists` on the partition key: both on Put and Update, `IfExists()` on Delete.

| Clause | Result |
|---|---|
| `ReturnOld()` | Put, Update, Delete: `ALL_OLD` in `WriteResult<T>.Item` |
| `ReturnNew()` | Update: `ALL_NEW`. Put: the item as stored, read with `T.ReadAttributes` from the request's item after the response, so no `ReturnValues` is sent, it costs nothing and holds the next version; the caller's entity is unchanged. On a put `ReturnOld()` and `ReturnNew()` replace each other |
| `Return(attr)` | Update: `UPDATED_NEW` of one attribute. Returns `ReturnCommand<,>`, which only sends; `SendAsync` gives the value. A missing attribute throws `DynamoDbMappingException`, never a default |
| `ReturnOldOnFailure()` | Put, Update, Delete, transaction steps: the item on `ConditionalCheckFailedException.Item`, on `WriteResult<T>.Item` with `TrySendAsync`, or via `ItemFor` in a transaction |
| `StoreKeyInputs()` | Update of an entity and `UpdateStep`: stores the table key's inputs as attributes, section 8. Does not compile on `Table<Item>`; throws `InvalidOperationException` on a step of one |

`WriteResult<T>` has `ConditionMet`, `Item`, `HasItem`, `ConsumedCapacity`, `ItemCollectionMetrics` and `Version` (`long?`): null for a write that stored no version it knows (a delete, an update with `IgnoreVersion()`, a type without `[Version]`, a failed `TrySendAsync`). One nullable member and no non-null twin, because whether a write stores a version depends on the chain and the answer; code that knows writes `Version!.Value`.

```csharp
var result = await matches.Update(LiveMatch.Keys.Of(id)).Set(LiveMatch.Attrs.ScoreAt, at)
    .If(LiveMatch.Attrs.ScoreAt.NotExistsOrLt(at)).ReturnOldOnFailure().TrySendAsync(ct);
if (!result.ConditionMet) { /* old news, or stored already: compare result.Item!.ScoreAt with at */ }
```

**`TrySendAsync`** on Put, Update and Delete sends what `SendAsync` sends and takes a `ConditionalCheckFailedException` as its answer: `ConditionMet` false, `Item`/`HasItem` the item the condition saw when `ReturnOldOnFailure()` asked (read with the entity's reader, so a misfit throws `DynamoDbMappingException`), and `Version`, `ConsumedCapacity`, `ItemCollectionMetrics` null. `ConditionMet` is true on every `SendAsync` result and on `default`. Other errors throw as from `SendAsync`; `ReturnOld()`/`ReturnNew()` give nothing for a failed condition. On `ReturnCommand<,>` it returns `ReturnResult<TValue>`: `ConditionMet`, and `Value` as `SendAsync` reads it, or default when the condition failed; no `ReturnOldOnFailure()` item; `default` reads as a met condition. Transactions have no `TrySendAsync`. A failed condition of `TrySendAsync` is no conflict to `RetryOnConflictAsync`, no error on the span (`dynasharp.condition_met` = `false`) and no `error.type` on the duration. After a lost response the client's retry fails against its own first attempt, indistinguishable on the wire from a second delivery of the change; the `ReturnOldOnFailure()` item, compared with what was sent, tells that the change is stored.

**Retries repeat writes.** `Add`, `list_append` and arithmetic in `SET` apply twice if a response was lost. `MaxAttempts(1)` makes them at most once (a lost response then reports a failure after the write applied), a condition makes them exact. After a lost response a conditional write judges what its first attempt wrote, which each command's `SendAsync` docs spell out.

**Update actions by handle.** `Set` takes a nullable value and null is a `Remove`, for every attribute (`string?`; `Guid?` through an overload for value types). On a key input the rules of section 8 follow the `Set` or `Remove` it becomes. `SetIfNotNull(handle, value)`, by handle only, is that `Set` with a value and adds nothing with null (the attribute stays, a key input counts as untouched). `SetIfNotExists`, `Add` and `Delete` by handle reject null: a value type does not compile, a null reference is a nullable warning and `ArgumentNullException`. Raw paths exist for all actions as the escape hatch for attributes outside the entity, unchecked by section 8.

**`[OmitEmpty]`** writes an empty string or collection like null: `Put`, batches, transactions, `With` by handle and `Item.From` leave it out, `Set` by handle is a `Remove`, `SetIfNotNull` adds nothing, `SetIfNotExists` by handle throws `ArgumentException` (the base of what null gets). A stored `""` or `[]` still reads as is; a raw path writes what it is given. A missing attribute reads as always (empty set for a non-nullable set, else the initial value), so `[]` does not round-trip, null and `[]` can differ, and `[OmitEmpty(false)]` keeps the empty one. Wider than the AWS SDK, which drops empty strings but keeps empty lists of documents, dictionaries and `byte[]`. A `required` non-nullable non-set property, or such a constructor parameter without default, could not be read back: `DYNA030` on the property; type and assembly defaults pass over it, as over key inputs. The handle shows it in its converter (`NullableReferenceHandleConverter<string, OmitEmptyConverter<StringConverter>>`, `OmitEmptyCollectionConverter<T, TElement, TConverter>`, `OmitEmptySetConverter<T, TElement, TConverter>` for one `Add` takes), so nested paths keep it, and a type without the attribute generates what it did.

`IDynamoDbConverter<T>.IsOmitted` is the same question by value for a converter of your own (say, a list stored as a set, which DynamoDB refuses empty): every write above asks it and a value it counts as null goes the way of an `[OmitEmpty]` empty string, nested documents and handle paths included. The generated writer holds the call only for a `[DynamoDbConverter]` or `[DynamoDbDefaultConverter]` that implements `IsOmitted`, so built-ins pay nothing. Key inputs and collection elements are always written. A read does not ask.

## 8. What a write of an entity enforces

Raw paths and `Table<Item>` bypass all of this. Every enforced condition and action is visible in `ToRequestJson()`; the checks run at the terminal and cost an entity without them nothing. A failed condition is the ordinary `ConditionalCheckFailedException`; nothing retries or reads implicitly.

**`[Version]`.** The property holds the version the caller last read; 0 means no item exists.

| Write | Rule |
|---|---|
| `Put(entity)` | Version 0 adds `attribute_not_exists(<partition key>)`, on the key, not the version, so it fails on any item under the key, also one without a version (`VersionMissing.Allow` is for tables that keep such items; for one item `Put(entity).IgnoreVersion()` takes it over and stores version 1). Otherwise `<version> = :old`, and the item stores `old + 1`. The entity is not mutated: `WriteResult<T>.Version` is the stored version |
| `Put(entity).IfNotExists()` | Legal at version 0, the clause once. Above 0 the terminal throws `InvalidOperationException` (also on a transaction step and `Unique`), because no item can lack its key and hold a version, unless `.IgnoreVersion()`. `DYNA206` where visible |
| `Put(entity).IfExists()`, `Update(key).IfVersion(0).IfExists()`, `Delete(entity).IfExists()` | Legal above 0. At version 0 the terminal throws `InvalidOperationException` naming the entity, in either order, also on transaction steps and `ConditionStep`, unless `.IgnoreVersion()`: both conditions would go out and always fail |
| `Update(key)` | `.IfVersion(n)` adds the condition (at 0 `attribute_not_exists(<partition key>)`) and `SET <version> = :new` with `n + 1`. Without it the terminal throws `InvalidOperationException` naming the entity, unless `.IgnoreVersion()`. There is no `Update(entity)` |
| `Update(key).IfVersion(n).IfNotExists()` | Legal at 0, either order, the clause once. Above 0 the terminal throws `InvalidOperationException`, also on `UpdateStep` and `ConditionStep` |
| `Delete(key)` | The same rule as `Update(key)`, with the condition alone |
| `Delete(entity)` | `IfVersion(entity.Version)`, so at 0 it fails on any item under the key. `IfVersion(n)` replaces it, `IgnoreVersion()` opts out |
| Transaction steps | The same rules: `IfVersion` on `UpdateStep` and `ConditionStep`, `IgnoreVersion` on all three |
| `BatchWrite` | A batch carries no condition, so a put or delete of a versioned entity throws at the terminal unless `.IgnoreVersion()` on the batch, which stores each put at its entity's version plus one |
| `Put(entity).IgnoreVersion()` | No version condition; stores `old + 1` as a checked put does (imports, migrations) |
| `Update(key).IgnoreVersion()` | No version condition; `SET <version> = if_not_exists(<version>, :zero) + :one` after every other action, so a new or version-less item gets 1. The update's own action on the version attribute (`Set`, `Add`, `Remove`, raw path) takes its place. `Version` of the result is null |

`IgnoreVersion()` after `IfVersion(n)` throws (the condition cannot be taken back out); `IfVersion(n)` after `IgnoreVersion()` wins. `IgnoreVersion()` drops the check, never the advance: every write of a versioned entity but a delete stores a new version, so a stale copy fails its next checked write instead of undoing it. `WriteAttributes` does not bump, so `Item.From` stays a plain copy.

**`VersionMissing`.** `[Version(Missing = VersionMissing.Allow)]` is for tables that keep items without the attribute, or holding 0 (the AWS SDK's first `SaveAsync`), which both read as 0. `Reject` is the default (the table above). In `DynamoDbEntityInfo.VersionMissing`.

| With `Allow` | Rule |
|---|---|
| Every version 0: `Put`, `IfVersion(0)`, `Delete(entity)`, transaction steps | `(attribute_not_exists(<version>) OR <version> = :v)` with 0, instead of the partition key condition. The first write replaces such an item and stores 1, a second write at 0 fails, and a write at 0 no longer proves the key was free |
| `IfNotExists()` at 0 | `attribute_not_exists(<partition key>)` alone and once, either order, `Unique` too |
| `IfExists()` at 0 | No longer throws; renders `attribute_exists(<partition key>) AND (attribute_not_exists(<version>) OR <version> = :v)`, either order |
| A read | 0 for an item without the attribute, also for a `required` version or a constructor parameter without default |
| `Select(Attrs.Version)` | 0 as well (its generated converter answers `TryReadMissing`, and is still a number for `Add`). No item is `Found == false` |

The condition of `IfVersion(0)` waits for the terminal, because `IfNotExists` can still replace it, so it stands after the chain's other conditions. Above 0 `Allow` changes nothing.

**Template inputs.** A typed `Set` or `Remove` by handle of a property that feeds a key template must leave that key consistent:

| The update | Result |
|---|---|
| Knows all inputs of an index template, set or from its key | Writes the derived attribute in the same `SET` |
| Lacks an input it could set | `InvalidOperationException` naming the template, what is missing and the `Set` to add (`.Set(WorkItem.Attrs.CreatedAt, value)` with the item's value), because an update expression can copy an attribute but not format a key of several values or literals. `DYNA226` |
| Lacks an input it cannot set | `InvalidOperationException` naming template and missing input, pointing at a `Put` of the changed entity or a raw path |
| Touches an input of a table key | `InvalidOperationException`: DynamoDB cannot update a key |
| Changes an input by `Add` or `SetIfNotExists` | `InvalidOperationException`: the value is not known |
| Changes by handle what a computed input derives from (`Set`, `SetIfNotNull` with a value, `Remove`, `Add`, `Delete`, `SetIfNotExists`, also of a path inside it such as `Attrs.Message.At(Msg.Attrs.Arrival)`) | `InvalidOperationException` naming property, computed input and template, pointing at a `Put` or a raw path: no update can run a getter. In a table key it is the row above |
| Writes by handle a `[ComputedFrom]` input that has its own attribute | The same: the key would follow the update, not the getter, and the next `Put` would move it |
| Removes an input of a sparse index | Removes the derived attributes, unless another index still holds the item |
| Removes an input of a non-sparse index | `InvalidOperationException` |
| Sets one key of a sparse index and does not produce the other | `InvalidOperationException` naming the other key and the `Set` that produces it where a handle can: an update does not read the item, and one without the other key would stay out of the index silently. `DYNA226` |
| Sets one key of a non-sparse index and does not produce the other | Writes the key it can compute and throws nothing (`.Set(Attrs.At, at)` renders `SET At = :v0, gsk = :v1`, no `gpk`). An existing item keeps its other key; a created item stays out of the index. An update that can create items sets every input, ends in `.IfExists()`, or is a `Put` |
| `StoreKeyInputs()` | Ends the `SET` with `#attr = if_not_exists(#attr, :v)` per table key input with its own attribute, after the actions and derived keys, before literal keys and the discriminator |

An update does not read: it can copy an attribute (`SET a = b`) but not format a key from attributes, so every input of a key it changes comes from the caller, also unchanged ones, and no key is written from some of its inputs. The copy is used for the other key of a sparse index (the one case that would throw otherwise) where the key is the attribute's stored text byte for byte: a template of one bare placeholder, no literal, over a property with an attribute, written by `StringConverter` (`{X:raw}` too), `GuidConverter`, `DateOnlyConverter`, `DateTimeConverter`/`DateTimeOffsetConverter` under `{X}` or `{X:ticks}`, or a generated enum-by-name converter. Nothing else qualifies: a number is `N` and DynamoDB rejects it for a string key, `d<w>` and `n<i>.<f>` pad or sign, other timestamp formats cut, literals and second placeholders are other text, and property or assembly converters (`SdkDateTimeConverter`) write what they like. A non-sparse index is not copied into, because an update that creates an item would then fail where it writes the computable key today. There is no way to name a value for the key alone: it would be a second `Set` that could disagree with the attribute.

An input of the table key is known from the update's key, so an index key mixing it with a changing property follows that property, and an index key made only of such inputs counts as produced, written in the same `SET` when the update writes the other key of its index. A generated key gives the value; a key given as strings goes through the generated parser, unless the table key's format loses what the index wants (a timestamp cut at the day): then a sparse index throws and a non-sparse one keeps the key a `Put` wrote; such an entity holds its generated key per update, one box, only for updates that write such a key. An index of only such keys is not written by an update that does not touch it: such items enter it by `Put`.

**`StoreKeyInputs()`.** Typed updates write no table-key input by default, so an `Update`-created item holds the key and not the attributes. With the clause it holds what a `Put` writes: `:v` as the property's converter writes it, never the key text (`EpochSecondsConverter` gives a number), `IsOmitted` not asked. The value comes from the update's key (a generated key holds it; strings go through the parser). Plain keys, single-placeholder templates over their property's attribute and `[KeyOnly]` inputs store nothing. A value no table key holds whole (`{At:yyyy-MM-dd}`) comes only from a generated key: with strings the terminal throws `InvalidOperationException` naming property and template, also when an index repeats the format. A key that does not fit its template throws. An action on the attribute by raw path wins; by handle it is the table-key row above. An existing item keeps what it has, so the clause pairs with `IfExists()`, `IfNotExists()`, `IfVersion` and `IgnoreVersion`. It costs an `AttributeValue` per input (plus the box of a generated key's value); an update without it pays nothing.

**Computed properties** are inputs like any other to `Put`, `Item.From`, batches and transaction puts (which run the getter), to the `Keys` builders, and to sparse indexes (a nullable one gates). A read leaves them alone. Only an update differs, having no instance: a `[ComputedFrom]` input has no value there, so its template is one whose input the update cannot set, unless it touches none of it. `SetIfNotNull` of null counts as untouched. A raw path is unchecked (`.Set("message", value)` goes out and the index keeps its key). `[ComputedFrom]` lists stored properties of the same type with their own attribute, one level: no computed property, `[DynamoDbIgnore]`, `[KeyOnly]` or `[Version]` (which an update moves without a handle). One of them may feed another key.

**Literal keys.** A key of literals only counts as produced on every index. When an update writes one key of an index, a sibling of literals is written in the same `SET`, so `PartitionKey = "ALL"` can be entered by `Update`; a `Remove` that takes the item out of a sparse index removes it too. An update that does not touch such an index adds nothing, unless all its keys are literals or table keys (no property can bring an item in): then every typed update writes the literals with `if_not_exists`, like the discriminator, so an update at a key held by another type does not overwrite them. An action on the attribute itself wins. A local index with a literal sort key is one of these.

**Discriminator.** `UpdateItem` can create the item, which must not be invisible to the typed API, so an `Update` of an entity with a discriminator ends its `SET` with `#_type = if_not_exists(#_type, :t)` (in transactions too), unless that attribute is a table key. An action on the attribute wins. A new item gets the type, an existing one keeps it.

## 9. Conditions and expressions

```csharp
using static DynaSharp.Expr;     // Attr("x"), Attr<int>("n")

shop.Update(pk, sk).If(Attr("status").Eq("open"));                                         // struct condition, untyped
orders.Query(pk).Filter(Order.Attrs.Total.Gt(100m).And(Order.Attrs.Lines.Lt(10)));         // typed, composed
shop.Update(pk, sk).If($"attribute_exists({Attr("pk")}) AND size({Attr("tags")}) < {10}"); // the grammar, for functions
shop.Update(pk, sk).Set($"{Attr("n")} = {Attr("n")} + {1}");                               // a raw action
orders.Update(key).Set(Order.Attrs.ShipTo.At(Address.Attrs.City), "Bern").IgnoreVersion();  // a nested path

private static readonly Condition Open = Condition.Of(Attr("status").Eq("open"));          // to keep in a field
shop.Update(pk, sk).If(Open & Attr("version").Eq(3));
```

Struct conditions cover comparisons, existence, `BeginsWith`, `Contains` and `Between`, compose with `And`, `Or`, `Negate` (`ConditionExtensions`) and allocate nothing. A chain of one operator renders as one group, `(a OR b OR c)`; conditions added one by one as `(a) AND (b) AND (c)`. `Condition.Of` keeps one in a field, composing with `&`, `|`, `!`. A handle has `NotExistsOrLt(v)` and `NotExistsOrLe(v)`, `(attribute_not_exists(a) OR a < :v)`, the guard against moving an item back to an older value and for something free or expired; no `Gt`/`Ge` forms (no use case), and none on `Attr` (a guard of typed fields).

`BeginsWith` by handle is an `AttrExtensions` extension because the attribute's type decides: number, boolean and number-stored timestamps do not compile (`CS0619`; DynamoDB finds nothing there); enums, `Guid`s and dates (strings) do; a binary attribute takes a binary prefix. A `[Flags]` enum (a number) has a converter no overload can name, so it compiles and `DYNA216` reports it. `Contains` by handle is an extension with one generated overload per handle of a set (an element, written by `SetElementValueConverter<T, TElement>`), a list (an element through the element converter) and a string (a substring), nullable and `[OmitEmpty]` included; anything else has none (`CS1929`). `Attr` has `Contains(AttributeValue)` and `Contains<TNumber>(TNumber)`. No `NotContains`: `Negate()` renders `NOT (contains(...))`, which holds where the attribute is missing.

Interpolation covers the rest of the grammar (`size`, `attribute_type`, `list_append`, arithmetic in `SET`). In a hole an `Attr` stands for its name, and an `AttributeValue`, a number or `handle.Value(x)` for a value; a string is a value, so a name needs `Attr` (`DYNA210`), and an expression naming no attribute throws `ArgumentException`. A bare name in the text goes out as is: a reserved word is rejected (`DYNA220`), one the command's type lacks is `DYNA213`; `begins_with`/`contains` on a number is `DYNA216`.

Every name becomes a placeholder and equal values share one, so reserved words need no care. A path is names joined by dots with list indexes in brackets; a dot always separates. `Attr` converts to its path as a `string`; `Attr<T, TConverter>` converts to `Attr` and not to `string`, so a wrong value type does not compile through a raw overload. `Expr.Attr<T>(path)` is a number handle, for `Return(...)` and typed `Add`. A custom condition implements `ICondition`.

## 10. Batches

```csharp
BatchGetResult<Customer> found = await customers.BatchGet()
    .Get(Customer.Keys.Of("alice"))
    .GetAll(ids.Select(Customer.Keys.Of))
    .SendAsync(ct);

BatchWriteResult written = await shop.BatchWrite()
    .Put(item)
    .Delete("USER#x", "PROFILE")
    .Put(orders, order)               // another type or table in the same batch
    .IgnoreVersion()
    .SendAsync(ct);
```

`BatchGet` reads one table in requests of 100 keys; `BatchWrite` takes any tables in requests of 25 writes that fit 16 MB. Requests run one after the other; what DynamoDB leaves unprocessed is sent again with the retry policy's backoff on the client's clock. `MaxAttempts(n)` is HTTP attempts per request; `MaxStalledRounds(n)` bounds requests in a row without progress, default 8. The verbs are the item's (`Get`, `Put`, `Delete`) with `All` for a sequence: `PutAll(IEnumerable<T>)`, `DeleteAll<TKey>(IEnumerable<TKey>)`, `GetAll<TKey>`; on an entity table `Delete(entity)` and `DeleteAll(IEnumerable<T>)` of `EntityTableExtensions` take each entity's key, so what a read returned is deleted as is (overload resolution drops the key form, whose constraint a sequence of entities fails).

A batch is not atomic. `BatchGetResult<T>` has `Items` (unordered, without missing keys), `ConsumedCapacity`, `Requests`; `BatchWriteResult` has `Written`, `Requests`, `ConsumedCapacity`, `ItemCollectionMetrics`. A batch that gives up throws `BatchIncompleteException` (`UnprocessedItems`, `Written`) or `BatchGetIncompleteException<T>` (`UnprocessedKeys`, the `Items` read so far), both `DynamoDbException` with code `BatchIncomplete`, whose contents go straight into the request API.

It gives up after `MaxStalledRounds`; on a failure the pipeline retries (throttle, timeout, lost connection, 5xx) after the last attempt of the first request; and on any failure after at least one request went through. The last two carry the failure as `InnerException`. A request without an answer may have applied in part, so all of it counts as unprocessed, which is safe to resend. A permanent failure of the first request (`ValidationException`) applied nothing and surfaces raw. The caller's cancellation stays `OperationCanceledException` without progress.

## 11. Transactions

```csharp
TransactMarker emailTaken = default;
try
{
    await client.TransactWrite()
        .Unique(markers, new EmailMarker(email, id), out emailTaken).ReturnOldOnFailure()
        .Put(customers, new Customer { Id = id }).IfNotExists()
        .Update(customers, Customer.Keys.Of("admin")).Add(Customer.Attrs.OrderCount, 1).If(Customer.Attrs.OrderCount.Lt(100))
        .Check(shop, "TENANT#1", "QUOTA").If(Attr("remaining").Gt(0))
        .Delete(shop, "CART#x", "ITEM#1")
        .SendAsync(ct);
}
catch (TransactionCanceledException e) when (e.ReasonFor(emailTaken) == TransactionFailure.ConditionalCheckFailed)
{
    string? holder = e.ItemFor(emailTaken)?.GetString("customerId");
}

TransactGetResult snapshot = await client.TransactGet()
    .Get(customers, Customer.Keys.Of("alice"), out TransactSlot<Customer> slot)
    .Get(shop, "TENANT#1", "QUOTA", out TransactSlot<Item> quota)
    .SendAsync(ct);
Customer? read = snapshot.Read(slot).Item;
```

`Put` returns a `PutStep`, `Update` an `UpdateStep`, `Delete` and `Check` a `ConditionStep`; each has its own clauses and the verbs of the next action, so `.Add(...)` after `.Put(...)` does not compile. The verbs, `IfExists`, `IfNotExists`, `ReturnOldOnFailure`, `Token`, `ReturnCapacity`, `ReturnMetrics` and `SendAsync` are extensions of `TransactWriteExtensions` over `ITransactWriteChain<T>`/`ITransactWriteStep<T>`. Every verb that starts an action has an `out TransactMarker` form. A transaction takes 100 actions; the next verb throws `InvalidOperationException`, as does sending none.

Each step converts implicitly to `TransactWriteCommand`, so a loop reads `TransactWriteCommand tx = client.TransactWrite(); foreach (...) { tx = tx.Put(table, item).IfNotExists(); }`. `PutAll(table, items)` is that loop without clauses, returning a `TransactWriteCommand`; a `[Version]` entity gets its version check per item; action 101 throws as any verb does. `Token(string)` sets `ClientRequestToken`; without it each send generates one, carried by every retry of that send.

`Unique(table, item, out marker)` is a put with `attribute_not_exists` on the partition key; `Unique(table, key, out marker)` writes a marker item of the key only. `TransactionCanceledException` has `ReasonFor(marker)` (`TransactionFailure`), `ItemFor(marker)` (`Item?`), `Failures` (`TransactionActionFailure(Index, Reason)`) and `CancellationReasons` (raw). `TransactWriteResult` has `ConsumedCapacity` and `ItemCollectionMetrics`, no stored versions.

`TransactGetCommand.Get` takes a table and a generated key with `out TransactSlot<T>`, or a `Table<Item>` with partition and optional sort key and `out TransactSlot<Item>`. Write verbs take key values only with a `Table<Item>` (section 3). `TransactGetResult.Read(slot)` parses on demand into a `GetResult<T>`.

## 12. Mixed-type reads

```csharp
await foreach (Mixed<Customer, Order> row in shop.Query(pk).Of<Customer, Order>().ItemsAsync(ct))
{
    if (row.Is(out Customer? customer)) { }
    else if (row.Is(out Order? order)) { }
}
```

`Of<...>()` (`MixedExtensions`) extends `QueryCommand<Item>` and `ScanCommand<Item>`, on a table or `Index<Item>`, with 2 to 4 entity types, and returns `MixedQueryCommand<TMixed>`/`MixedScanCommand<TMixed>` with the same read clauses and the terminals of section 5; the scan also has `Segment` and `Parallel`. `TMixed` is the item, `Mixed<Customer, Order>`, so one command type serves every arity (call sites use `var`). Its constraint `IMixed<TSelf>` is an `IDynamoDbDocument<TSelf>` only `Mixed<...>` implements (its one member, the schema of the mix, is internal). Type arguments are constrained to `IDynamoDbDiscriminated<T>`, so an opted-out type does not compile; a hand-written type that claims it throws `ArgumentException`.

The filter gains `#_type IN (:a, :b)`, so other types never reach the client and `ScannedCount` can exceed `Count`; a table or index keyed by the discriminator skips it. Dispatch reads straight into the entity. `Mixed<...>` is a readonly struct with `Is(out T)` per type and `Match(...)`. Stream changes are typed by the same rule (`MixedChange<...>`, section 15). A read of `Table<T>` of an entity is unchanged. A mixed read of an index takes key names from an entity through `shop.Index<Membership>(Membership.Indexes.Gsi1)`.

## 13. Fan-out query

```csharp
await foreach (Order order in orders.Query(shardKeys, SortKeyCondition.Between(from, to)).Descending().ItemsAsync(ct)) { }
Page<Order> page = await orders.Query(shardKeys).PageAsync(pageSize: 50, after, ct);
```

`Query(IEnumerable<PartitionKey<T>>, SortKeyCondition)` on `Table<T>` and `Index<T>` (`EntityTableExtensions`), and on `Table<Item>`/`Index<Item>` also `Query(IEnumerable<AttributeValue>, ...)`, `Query(IEnumerable<string>, ...)` and `Query(ReadOnlySpan<string>, ...)` (`ItemTableExtensions`), return a `FanOutQueryCommand<T>`: one query per partition, merged. `Table<Item>`/`Index<Item>` take any entity's keys. The `IEnumerable<string>` form has `[OverloadResolutionPriority(-1)]`, so it never makes a call ambiguous that binds elsewhere; `Query(default)` and `Query([])` do not compile. Clauses: `Filter`, `Project`, `Limit` (items per partition page), `Descending`, `Consistent`, `MaxAttempts`, `ReturnCapacity`, `OnMappingFailure`, and `MaxConcurrency(n)`, default 8.

Items merge in DynamoDB's sort key order (bytes for S and B, numeric for N), ties by the partition key's position in the input. A partition is read only when the merge needs it, so an early `break` reads no more, and at most one page per partition is buffered. A repeated or empty partition key throws `ArgumentException`; an empty list reads nothing.

`PageAsync(pageSize, after, ct)` returns a `Page<T>` whose `Next` is a composite token: per partition its start key and the key of its next item as a hint (or done), plus the direction. The hint spares reading a partition the merge does not need yet and never reaches a request. A token of another partition list fails a count check, one of the other direction is rejected, and every shape error throws `FormatException`, as `Parse` does, before a request, so a web handler has one thing to catch; `ValidationException` remains for a start key only DynamoDB can judge. A signing client signs over the partition keys too (section 6). If the table changes between pages, an item written before a hinted key can come later than its place. `Page.ConsumedCapacity` adds every response of that call. Not a snapshot; no `PagesAsync`, no `Parallel`.

## 14. Item and AttributeValue

`Item` is the flat item: a sealed mutable `IReadOnlyDictionary<string, AttributeValue>` that compares by content and implements `IDynamoDbDocument<Item>`, which makes `Table<Item>` the same engine. Build it with the indexer; `Remove(name)` says whether the attribute was there; `item["x"]` throws `KeyNotFoundException` naming the attribute. `GetString`, `GetNumber<T>`, `GetBool`, `GetBinary`, `GetMap`, `GetList`, `GetStringSet`, `GetNumberSet`, `GetBinarySet` return null for a missing attribute or NULL and throw `InvalidOperationException` for another type; a number that does not fit throws `FormatException`/`OverflowException`. Messages name the attribute, never the value; `ToString()` is DynamoDB JSON, values included. `Item.From(value)` and `item.To<T>()` convert to and from a mapped type.

`item.Is<T>()` says whether the item's discriminator attribute (`_type` or the type's `AttributeName`) holds a string equal to `T`'s discriminator, the rule of mixed reads, from one `DiscriminatorSchema`; missing, NULL or another kind is false; constrained to `IDynamoDbDiscriminated<T>`, a hand-written type without a discriminator throws `ArgumentException`; allocates nothing. It reads no other attribute, so a `T` can still fail `To<T>()`. No `TryTo<T>(out T)`: a `Try` that throws a mapping failure breaks the pattern and one that returns false hides it, so callers write `Is<T>()` then `To<T>()`. An `Item` inside an `AttributeValue` (what `GetMap` returns) is read-only, visible at run time only (a separate type would repeat every getter); `new Item(other)` makes an editable copy. Read items have no attribute order, hand-built ones keep insertion order, and `Equals` is the only sanctioned comparison. Its hash follows its content, so it does not belong in a `HashSet`.

`AttributeValue` is a struct with implicit conversions from `string`, `bool`, `int`, `long`, `double`, `decimal`, `byte[]` and `char` (a one-character string). `Null` and the `FromXxx` factories cover the rest, `AsXxx` reads, numbers stay text until read, `ToString()` is DynamoDB JSON.

**Numbers.** DynamoDB holds 38 significant digits, a `decimal` 28 to 29 with at most 28 after the point. A `decimal` read returns the exact value or throws `OverflowException` on every path (`NumberConverter<decimal>`, `DynamoDbReader.GetNumber<decimal>`, `Item.GetNumber<decimal>`, `AttributeValue.AsNumber<decimal>`), never rounds (`1E-29` is no 0), and accepts value-keeping trailing zeros and exponents (`1.10`, `1E+2`, `0E+5`). For all 38 digits, `AsNumber()` and `DynamoDbReader.GetNumberText` give the text. `double`, `float` and `Half` round to nearest and read underflow as 0; a number that rounds to infinity, and `NaN`, throw `OverflowException`.

**Plain JSON.** `AttributeValue.FromJson(JsonElement)` and `FromJson(ReadOnlySpan<byte> utf8Json)` map one JSON value: object `M`, array `L`, string `S`, number `N` with its text, `true`/`false` `BOOL`, null `NULL`; a null in an object is left out, in an array it is `NULL`; empties stay. The bytes are RFC 8259 (`JsonException` otherwise; an element may come from a lenient parse). `ArgumentException`, naming the JSONPath (`$.lines[2].weight`, `$['a b']`) and never a value, for what DynamoDB refuses: over 38 significant digits, magnitude outside 1E-130 to below 1E+126, over 32 levels (a scalar is one), an empty name, a duplicate name, invalid UTF-8 or a lone surrogate, `default(JsonElement)`. `ToJson()` returns a self-owned `JsonElement`; `WriteJson(Utf8JsonWriter)` writes with the caller's settings: numbers as stored text (never through `double`), `SS`/`NS` as arrays, `B`/`BS` as base64, `NULL` as null. A `default` value throws `InvalidOperationException`; a `FromNumber(string)` that is no JSON number `FormatException`. DynamoDB canonicalizes numbers, so a round trip can change text (`1.50` to `1.5`), never value. No `Item.FromJson`: `new Item(AttributeValue.FromJson(json).AsMap())` and `AttributeValue.FromMap(item).ToJson()` cover it until a need comes up.

`JsonElementConverter` (`DynaSharp.Serialization`) is the built-in converter of `JsonElement`, so such a property (alone, nullable, in a list or dictionary) maps without an attribute. It writes and reads as above, its `ArgumentException` becomes one naming type, property and attribute on the generated write, it reads any stored type, a null `JsonElement?` is left out, and it is no key type. Paths inside it are strings (`Set("Label.to", ...)`, `Attr("Label.to")`, `Project("Label.to")`); `.At(...)` is for documents. `JsonDocument` has no converter (it needs a disposal a read has nobody for), nor `JsonNode` (convert with `JsonSerializer.SerializeToElement`).

A string with a lone surrogate is no text: `DynamoDbWriter` throws `ArgumentException` for it in values, string sets and names, as expression text and keys do, rather than store U+FFFD. `ToString()` shows U+FFFD, being the text read while debugging.

## 15. Errors and escape hatches

`DynamoDbException` carries `ErrorCode` (the wire code without namespace), `StatusCode`, `RequestId`, `OperationName`, `TableName` and `IsTransient`. A known code has its class in `DynaSharp`, any other is a plain `DynamoDbException`. `DynamoDbMappingException` and `CredentialsUnavailableException` are there too, so a catch needs no other import. There is no base type for client-side failures: `TimeoutException`, `HttpRequestException`, `OperationCanceledException` and `CredentialsUnavailableException` (which also carries what STS answers) keep their types, because wrapping would break every `catch (TimeoutException)`.

`IsTransient` (named after `DbException.IsTransient`) is true when the same call can succeed later unchanged: everything `FailureClassifier.Classify` repeats (throttling and capacity, `TransactionInProgressException`, 500, 502, 503, 504, `RequestTimeoutException`, `ReplicatedWriteConflictException`), so the two cannot disagree, plus `TransactionConflictException` and a cancelled transaction whose failed actions are all `TransactionConflict` or `Throttled`, which the pipeline leaves to the caller. A batch that gave up is true without a cause (its rounds ran out), else as its `InnerException`. Everything else is false: validation, missing or busy table or index, access, signature and token codes, failed conditions, other cancelled transactions, size limits, unknown codes below 500. The client retried before it surfaces, so true means its attempts ran out.

| Failure | Where |
|---|---|
| A bad key of `Table<Item>`: empty string, empty binary, or a sort key on a table opened without one | `ArgumentException` at the call |
| A typed key from bad input | `KeyFormatException`, an `ArgumentException` naming the placeholder, never the value; from a generated builder it names the template, and for a delimiter the template's delimiters: `The value contains a delimiter of the key template 'USER#{Id}' ('#'). (Parameter 'Id')` |
| A rejected request of a command | `ValidationException` with `Expressions`, `ExpressionNames` (`#n0 = status`), `ExpressionValueTypes` (`:v0` is `S`) and a `Message` line `Expression: #n0 = :v0, where #n0 = status, :v0 (S)`; no values. In a transaction or batch get the entries are prefixed (`TransactItems[2].`) |
| An item that does not fit the type | `DynamoDbMappingException` with `EntityType`, `AttributeName`, `Key`, also for an item of another type (the discriminator value is named: it is a type tag). A stored key that does not fit its template says so without the value. `Key` is the table's key attributes of the item, on `Get`, `Query`, `Scan`, fan-out, `BatchGet` and mixed reads (null after `Select` on `Query`/`Scan`); message and telemetry never show it. `OnMappingFailure`, section 6 |
| A failed condition | `ConditionalCheckFailedException` with `Item` (when `ReturnOldOnFailure()` asked) and `Key`. `Message` gains a line naming the condition sent, never a value: `The condition of this Update on Users did not hold: the version check on Revision.`, or the key checks, or the caller's condition, with `and DynamoDB does not say which` when several; a new-item version adds that the check asks for no item at the key and that the version last read or `IgnoreVersion()` writes over it. `Key` is the item's key as the request named it (stored values such as `USER#alice`), read from the sent body on the failure path only: of `Update` and `Delete`, the key attributes of a `Put`'s item, `request.Key` of `UpdateItemAsync`/`DeleteItemAsync`; null on `PutItemAsync` (no key names), `SendRawAsync`, in a transaction (`ItemFor` is that) and off a response. `T.Keys.Pk.Parse(key.GetString("pk"))` gives the inputs back. It is for code that does not hold the key, such as a wrapper around a delegate. Never in message, `ToString()`, logs or telemetry |
| A transaction | Section 11. `ConditionalCheckFailed` and `ValidationError` do not pass on retry, `TransactionConflict` and `Throttled` may. `Message` of a command names each failed action by position, verb, table and code: `Action 2 of 2, Put on Users: ConditionalCheckFailed` |
| A table `CreateTableCommand.IfNotExists()` found with another key | `InvalidOperationException` naming table, expected and found key. Not a new type: a configuration error no retry or handler fixes, met at start, where the program should stop |
| A wait for a table that runs out, or on `CreateTableCommand` does not see a declared index listed | `TableNotActiveException`, sealed, a `TimeoutException` with `TableName`, `LastStatus` (`TableStatus?`, null when the last look found no table, then `InnerException` is the `ResourceNotFoundException`) and `PendingIndex` (the index not active or not listed, also in the message). `catch (TimeoutException)` keeps working; `AttemptTimeout` on a poll gives the plain type |

Compile errors stand in for what would be a `ValidationException`, a mapping failure or an empty result: another entity's key in `Query`, stored key values on an entity table, writes on `Index<T>`, `Put()`/`With` outside `Table<Item>`, step-specific clauses, `Return(attr)` and `Select(handle)` ending the chain, `SortKeyCondition` operators, `Of<T>()` of entities only, no `PageAsync` after `Parallel()`, no `BeginsWith` on number handles.

Escape hatches: `client.SendRawAsync("ListTables", """{"Limit":1}"""u8.ToArray(), ct)` for what nothing models, with the pipeline's signing, retries and telemetry; raw paths and interpolated expressions on typed commands; `Item.From` and `To<T>`.

Out of the API on purpose: an interface on `Table<T>` or `DynamoDbClient`, `Save`, identity maps, lazy loading, any read before a write, `ToRequest()` on an item command, `==` on attributes, views and streaming callbacks over a response, compile-time expression templates. A write through `Table<Item>` is what it says: no `_type`, no key check.

### Streams

`DynamoDbStreamsClient` takes the same options and has `Options`, `ListStreamsAsync`, `DescribeStreamAsync`, `GetShardIteratorAsync`, `GetRecordsAsync`, `ReadShardAsync`, `ReadStreamAsync`, `SendRawAsync`. Response members are nullable as the service model has them (botocore's `dynamodbstreams` marks none required but `KeySchemaElement`'s), so a missing one reads as null and nothing throws. `StreamRecord.NewImage`/`OldImage` are `Item`, so `To<T>()` reads an image and `Is<T>()` tells entities apart. There is no consumer, by scope: no leasing, checkpoint store or lineage scheduler, no sharing of shards across processes. `docs/streams.md` is the guide.

**`ReadShardAsync(ReadShardRequest, ct)`** returns `IAsyncEnumerable<ChangeRecord>` of one shard: `StreamArn`, `ShardId`, a required `ShardIteratorType` with `SequenceNumber` exactly for the two sequence positions (`ArgumentException` otherwise, `ArgumentOutOfRangeException` for `Unknown`), `Limit` per `GetRecords`, and `EmptyPageDelay` (default 1 s, from zero to below the 15 minutes of an iterator), waited on the client's `TimeProvider` after an empty page of an open shard. Arguments are checked at the call; requests start at the first `MoveNextAsync`. An expired iterator is renewed `AfterSequenceNumber` of the last record returned, or at the request's position before the first; one expired at once surfaces `ExpiredIteratorException`. The sequence ends on a page without `NextShardIterator` or a `GetShardIterator` without an iterator. `TrimmedDataAccessException` surfaces (data was lost). The checkpoint is each record's `StreamRecord.SequenceNumber`; records, not pages, are returned, because the position is per record.

**`ReadStreamAsync(ReadStreamRequest, ct)`** returns `IAsyncEnumerable<ShardChangeRecord>` of every shard of one stream, read in this process. `ReadStreamRequest` is `StreamArn`, a required `ShardIteratorType` of `TrimHorizon` or `Latest` (`ArgumentOutOfRangeException` otherwise), `EmptyPageDelay` and `OnJoined` (`Action?`), nothing else (no limit, buffer, retry or resume settings). `ShardChangeRecord` is a `readonly struct` of `ShardId`, `Record` and computed `SequenceNumber` (`Record.DynamoDb?.SequenceNumber`, null for `default`), with value equality, `Deconstruct` and `ToString` written out (not a `record struct`, whose `Equals(object)` lacks a nullable annotation); the shard is not on `ChangeRecord` because `GetRecords` does not say it. Arguments are checked at the call, requests start at the first `MoveNextAsync`.

- **Shards.** Listed with `DescribeStream`, every page. `TrimHorizon` starts each shard whose parent is not listed, closed or open, from the trim horizon; `Latest` starts each open shard at `Latest`, and watches a shard closed at the start for children as one read to its end, excluding its children listed at the start unless the first of them opened over a minute ago by its id; a child listed later is read from its first record. Each shard runs `ReadShardAsync` on its own task; one read to its end starts its children, found with a `ShardFilter` of `CHILD_SHARDS` and kept only if their `ParentShardId` names it. A child whose id (`shardId-<20 digits of Unix ms>-...`) says it opened under 23 hours ago on the client's clock starts at the trim horizon (nothing can be trimmed yet), otherwise `AT_SEQUENCE_NUMBER` of its `StartingSequenceNumber` (so trimmed records give `TrimmedDataAccessException`), or the trim horizon without one. Each child starts as soon as listed; the parent's reader keeps looking while the stream is `ENABLED` or `ENABLING`, every `EmptyPageDelay` but at least every second until a first child, then every 5 s (or `EmptyPageDelay` if longer) for one more minute, because DynamoDB can list a child late and bounds no number of children.
- **Order and end.** Records pass a bounded buffer of 16. An item's changes come in order, different shards' in none. The sequence ends when no shard is left, which needs a disabled stream. The first failure that is not retried ends it with that exception, after the other readers were stopped and awaited; buffered records are dropped. Nothing is skipped: `TrimmedDataAccessException` surfaces, and a closed shard whose `GetShardIterator` gives `ResourceNotFoundException` (removed 24 h after closing) throws `TrimmedDataAccessException` with the original's request id and status. Cancelling or disposing stops every reader and waits for it.
- **Retries.** A shard is read again after a transient failure of the last attempt of a call (`IsTransient`, or what the retry classifier repeats: network failures, attempt timeouts): `GetRecords` again with the same iterator, `GetShardIterator` for the same position, an iterator expired meanwhile renewed as on any expiry, a failed look for children repeated. Full jitter from 1 s doubling to 30 s on the client's clock, for at most 15 minutes from the failure that started the outage, which a page or successful look ends; then the failure surfaces. The first listing is not repeated.
- **`OnJoined`** is called once on a reader's task when every starting shard (under `Latest` those open at the start, under `TrimHorizon` those without a listed parent) holds an iterator or has none to hold, or after the listing when there is none; not after a failure or stop. Its exception fails the reading. A write acknowledged after the call is read.
- **Telemetry.** Each shard is an `Internal` span `DynamoDB Streams.ReadStream` under the span current at the first `MoveNextAsync`, linked to its parent shard's, with `dynasharp.stream.shard_id`, `dynasharp.stream.record_count` and, when read again, `dynasharp.stream.retry_count`. `dynasharp.client.stream.shards` (`{shard}`, up-down) and `dynasharp.client.stream.records` (`{record}`) carry `server.address`, `server.port`; `dynasharp.client.stream.retries` (`{retry}`) those and `error.type`. Logs: 10 (Debug) a shard read to its end with its child count once the looks end, 11 (Debug) a child listed only on a later look, 12 (Warning) the start of a shard's outage, once, 13 (Information) its end.

`TableStreamExtensions.ReadStreamAsync<T>(this Table<T>, DynamoDbStreamsClient, ShardIteratorType, TimeSpan? emptyPageDelay = null, Action? onJoined = null, CancellationToken)` checks arguments at the call and starts each enumeration with `DescribeTable` through `Table<T>.Client`: `StreamSpecification.StreamEnabled` must be true and `LatestStreamArn` set, else `InvalidOperationException` naming the table; the view type is not checked. The streams client is a parameter, because making one from the table's client would be a hidden `HttpClient` per enumeration that ignores the application's configured streams client.

**Typed changes.** A stream cannot be filtered at its source, so a table of several entities streams them all, and the reader types each record from its images by the rule of `Item.Is<T>()`. `ChangeRecord.As<T>()` (`where T : IDynamoDbEntity<T>`) returns `Change<T>?`, null when neither image is a `T` or the record has no `DynamoDb`. An entity without a discriminator takes every image; a hand-written type whose `Info` has none is treated the same (where `Is<T>()` throws). `Change<T>` is a `sealed record` with `Kind` (`OperationType`, never `Unknown`), `Before`/`After` (`T?` from `OldImage`/`NewImage` by `To<T>()`, `default` of a struct entity where absent), `Keys` and `SequenceNumber` of the record, computed `Id` and `At`, and the required `Record` (which carries `UserIdentity`). `ChangeRecord.Id` is `EventId`, or `DynamoDb.SequenceNumber` when `EventId` is null or empty (DynamoDB Local sends it empty); `ChangeRecord.At` is `DynamoDb.ApproximateCreationDateTime`; both computed, so equality and `with` stay over the wire members. The kind follows the images of a `T`: both `Modify`, new only `Insert`, old only `Remove`, except a `MODIFY` whose other image the view omits, which stays `Modify`. So a discriminator that changes at its key (old `A`, new `B`) is `Remove` of `A` and `Insert` of `B`, both with the record's sequence number. An image of a `T` that `T` cannot read throws `DynamoDbMappingException` with `Key` a copy of the record's keys. By view: `NewAndOldImages` types everything; `NewImage` has no `Before`, no removal, and shows a type change as a `Modify` of the new type; `OldImage` has no `After` and no insert; `KeysOnly` gives null.

`TableStreamExtensions.ReadChangesAsync<T>(this Table<T>, DynamoDbStreamsClient, ShardIteratorType, TimeSpan? emptyPageDelay = null, Action? onJoined = null, Action<DynamoDbMappingException, ShardChangeRecord>? onMappingFailure = null, CancellationToken)` (`where T : IDynamoDbEntity<T>`) yields `Change<T>`; the instance methods `Table<T>.ReadChangesAsync<T1, T2>` to `<T1, T2, T3, T4>` with the same parameters (`IDynamoDbDiscriminated<T>`) yield `MixedChange<...>`, on every table, whatever its `T`, since they need only its client, name and keys. They are members and not extensions over `Table<TTable>` because explicit type arguments must name every type parameter, an extension block's included (C# 14), so `orders.ReadChangesAsync<Customer, Order>` could not bind; without type arguments no member can infer `T1`, so the call binds to the one-type extension. They read as `ReadStreamAsync` of the table, with its arguments and checks, and the starting `DescribeTable` also requires `StreamViewType.NewAndOldImages` (else `InvalidOperationException` naming table and view), since under `NewImage` a removal and under `OldImage` an insert could not be typed and would vanish silently. Types that cannot be told apart throw `ArgumentException` at the call. Changes of other types are skipped; a type change gives the old type's removal, then the new type's insert, each if its type is read. `onMappingFailure` is `OnMappingFailure` of a query: null throws, otherwise the failing change alone is skipped after the callback, which runs on the loop and also gets the `ShardChangeRecord`, so a log names the skip by `ShardId` and `SequenceNumber` (the docs say the record carries images and is not logged whole); it counts in `dynasharp.client.operation.skipped_items` with `db.operation.name` `GetRecords`, the table and the streams server. No new span, metric or log.

The names say what comes back: `ReadStreamAsync` gives a stream's records on any table, as `DynamoDbStreamsClient.ReadStreamAsync` does by ARN, and `ReadChangesAsync` typed changes. A typed `ReadStreamAsync<T>` would be raw on `Table<Item>` and typed on `Table<Order>`, and leave a typed table's reader that keeps shard positions without a raw reading; `ChangeRecord.As<T>()` types one record of it.

`MixedChange<T1, T2>` to `<T1, T2, T3, T4>` is a readonly struct with `Is(out Change<Tn>? change)` per type and `Match` with functions and with actions: to `Change<T>` what `Mixed<...>` is to an entity. Not one union for both: `Mixed<...>` is a document that query reads fill through `IDynamoDbDocument` (`QueryCommand<Mixed<...>>`, `Page<...>`, `ParallelScanCommand<Mixed<...>>`), holding entities unboxed and written by `Item.From`, while a change is neither read nor written as an item. Its `default` holds nothing: `Is` is false, `Match` throws `InvalidOperationException`. A public constructor per type (`new MixedChange<T1, T2>(Change<T1>)`, `ArgumentNullException` for null) lets a test build a handler's input; two equal types make the call ambiguous, which a reading rejects too (`ArgumentException`). `Mixed<...>` has none.

### Credentials

`docs/credentials.md` is the guide. `DefaultCredentialsProvider` is the chain of environment, web identity token file, shared files, container endpoint and instance metadata, in botocore's order; a source that applies but is broken fails instead of falling through. The single sources are `EnvironmentCredentialsProvider`, `WebIdentityCredentialsProvider`, `ProfileCredentialsProvider`, `ContainerCredentialsProvider`, `InstanceMetadataCredentialsProvider`, `AssumeRoleCredentialsProvider`, `SsoCredentialsProvider`, `StaticCredentialsProvider`. Provider requests never go through `HttpHandler`.

- **Web identity.** From `AWS_WEB_IDENTITY_TOKEN_FILE`, `AWS_ROLE_ARN`, `AWS_ROLE_SESSION_NAME`, or `new WebIdentityCredentialsProvider(tokenFile, roleArn, region, roleSessionName = null)` or `(tokenFile, roleArn, stsEndpoint, roleSessionName = null)`; a profile with `web_identity_token_file` and `role_arn` (and `role_session_name`) gets the same provider. The token goes to the regional STS endpoint of the client's region; `AWS_STS_REGIONAL_ENDPOINTS=legacy` selects the global endpoint for the regions botocore keeps there; `AWS_ENDPOINT_URL_STS`, then `AWS_ENDPOINT_URL`, go ahead of both (botocore's order, the rules of `ServiceUrl`), and then no region is needed. `stsEndpoint` goes ahead of all (same rules, `ArgumentException` otherwise): explicit settings replace the environment, so that constructor reads no variable, while the variables still win over the region form. A loopback endpoint bypasses the default proxy.
- **Environment.** `AWS_CREDENTIAL_EXPIRATION` (ISO 8601) goes into `Expiration`, as botocore's `EnvProvider` does: with it the provider rereads the environment through the refresh cache and `TryInvalidate` drops the credentials and returns `true`; without it the credentials never expire, are read once, and `TryInvalidate` returns `false`. An invalid or past time throws naming the variable.
- **`credential_process`.** `ProfileCredentialsProvider` runs it in botocore's place, between the static keys of the credentials file and those of the config file. The command line splits as botocore's `compat_shell_split` (C runtime rules on Windows, `shlex.split` elsewhere); the program runs without a shell, standard input closed, 20 s and 64 KB of output, parsed as `Version` 1. Credentials with an `Expiration` refresh through the cache and `TryInvalidate` reruns the program; static profile keys answer `false`. Messages name profile and exit code, never output or standard error.
- **Assume role.** `new AssumeRoleCredentialsProvider(sourceCredentials, roleArn, roleSessionName = null, options = null)` calls STS `AssumeRole` with any provider's credentials: a Query-protocol form signed with SigV4 (service `sts`), the endpoint rules and retries of web identity (`AssumeRoleOptions.StsEndpoint`, `AWS_ENDPOINT_URL_STS`, `AWS_ENDPOINT_URL`, `AWS_STS_REGIONAL_ENDPOINTS=legacy`, the regional endpoint). `AssumeRoleOptions` has `ExternalId`, `Duration` (15 minutes to 12 hours, whole seconds), `Region`, `StsEndpoint`, all `init`. The global endpoint signs for `us-east-1`, a configured endpoint for the known region or else `us-east-1`. An `IRefreshableCredentialsProvider` refreshing through the cache; no MFA. A profile with `role_arn` and `source_profile` or `credential_source` builds one in botocore's order with its checks; the STS region is the client's, else `AWS_REGION`, `AWS_DEFAULT_REGION`, the profile's `region`.
- **SSO.** `new SsoCredentialsProvider(startUrl, ssoRegion, accountId, roleName, sessionName = null)` reads the token `aws sso login` cached in `~/.aws/sso/cache/{sha1 of the session name, or the start URL}.json` at every fetch and calls the portal's `GetRoleCredentials` (`GET /federation/credentials?role_name=&account_id=` with `x-amz-sso_bearer_token`; `AWS_ENDPOINT_URL_SSO`, `AWS_ENDPOINT_URL`). With a session, a token in its last 15 minutes is renewed through OIDC `CreateToken` (`AWS_ENDPOINT_URL_SSO_OIDC`) and written back keeping file permissions; a failed renewal is logged and the cached token used while it lasts. A missing or expired token and HTTP 401 fail with a message to run `aws sso login`. `startUrl` is a `string` because the cache file is named by its SHA-1 as written. A profile is SSO when it has `sso_account_id` or `sso_role_name`, in botocore's place after web identity, with `sso_session` from a `[sso-session name]` section or the older keys, and the checks of botocore's `_load_sso_config`.

## 16. DynaSharp.Testing

The wire is the seam, and it serves every API. A test hands a client a `StubHandler`, queues responses and asserts on `stub.Requests`. `StubClient.Create(handler, configure = null)` and `StubClient.CreateStreams(handler, configure = null)` make the clients: fixed region `us-east-1`, static fake credentials, `MaxAttempts = 1`, no attempt timeout, nothing read from the environment or AWS files; `configure` adjusts the options as a `with` (the client validates the result). `ToRequestJson()` is the second seam, without a client. Credentials are not behind the seam (section 2), so a test without `StubClient` sets `Credentials`. `docs/testing.md` is the guide.

```csharp
using var stub = new StubHandler();
using var client = StubClient.Create(stub);
stub.Enqueue(StubResponse.Item(customer));

using var retrying = StubClient.Create(stub, options => options with { MaxAttempts = 4, TimeProvider = clock });
```

There is no attempt timeout because `AttemptTimeout` runs on `TimeProvider`, so a fake clock that the test moves would time out the request being answered; a test of a timeout sets one. A wait for a table runs on that clock too, so a loop advancing it with `Task.Yield` burns the whole timeout: such a wait takes a timeout the loop does not reach, or the clock moves once per poll the handler saw.

The helpers that take entities go through `WriteAttributes`, so they cannot drift from the codec; `Items` takes entities as well as `Item`s.

**A response of the wrong operation throws.** A factory's response carries the operations its body is for, and `StubHandler` compares them with the request's `X-Amz-Target`, whether the response came from the queue, the responder or `DefaultResponse`; a mismatch throws `InvalidOperationException` naming both operations and the response's queue position, because the client reads most such bodies without complaint (an `UpdateTimeToLive` answer taken by a `GetItem` reads as no item, and a miss test passes for the wrong reason). `ConditionalCheckFailed` answers `PutItem`, `UpdateItem`, `DeleteItem`; `TransactionCanceled` the two transactions; `ResourceNotFound`, `ResourceInUse`, `Json`, `DynamoDbError` and `new StubResponse()` fit any. No switch to turn it off: a body for another operation is written with `Json`. A response left in the queue is no error (failing it by default would break suites that queue one too many); `ThrowIfResponsesLeft()` is the opt-in, and `Dispose` never checks.

**Members of a recorded request.** `TableName`, `IndexName`, `ConsistentRead`, `ScanIndexForward` and `Limit` read the top-level member as sent, `null` where absent. The name map stays with `BodyJson`: its keys are the placeholder numbering the texts below hide.

**Text of a recorded expression.** Each text is the expression with placeholders resolved from its maps, or `null` without such an expression. One pass reads each placeholder to its end (`:v1` is no prefix of `:v10`) and does not reread what it put in. Keywords, functions and spacing stay as sent; a placeholder the maps lack stays, which is the mistake a test should see. Names stand as they are, document paths too, in backticks if they hold a dot or bracket (`` `a.b` `` is one attribute, `a.b` a path). Values read in PartiQL notation with double quotes:

`TransactItems` reads `TransactWriteItems` and `TransactGetItems` step by step (empty otherwise), each step resolving with its own maps. `BatchWriteItem` stays with `BodyJson`.

**Answers of administration and streams.** A body holds what DynamoDB sends, within the service model. `Table(name, status, indexes)` is an on-demand table with string key `pk`; `GlobalIndex(name, status)` an index with one key attribute named after it. `Table<T>(name, status)` has the entity's keys, types, local indexes and every declared global index as active, built as `CreateTable()` builds them, so a wait for declared indexes ends on it; `Table<T>(status = Active)` uses the declared name (`DYNA238` covers it). It lists one entity; a table of several takes indexes by name. `TableCreated` defaults to `CREATING`, `TableUpdated` to `UPDATING`, with indexes in the status each was given (`GlobalIndex(name, IndexStatus.Creating)` for one being added). `TableDeleted` holds what the API reference shows, without keys and indexes. `TablesListed(names)` is the last page of `ListTables`, `TablesListed(names, lastEvaluatedTableName)` one more pages follow, names in the order given; a mismatch on `UpdateTable` or `ListTables` names these two. `Count(count, scannedCount)` has no `Items` and takes a last evaluated key as `Items` does. `StreamDescription(tableName, shards)` is an `ENABLED` stream, `StreamDescription(tableName, status, shards)` one in that status (`Unknown` sends none), so a script whose last shard closes says `DISABLED` and `ReadStreamAsync` ends. `Records(nextShardIterator, ...)` numbers records without `EventId` or `SequenceNumber`; a `null` iterator ends a closed shard. Unstated values are fixed so answers do not depend on the clock: the region of `StubClient`, account `123456789012`, time 2026-01-01. `StubResponse.Table<T>(name)` and `BatchItems<T>(tableName, items)` take a name, since an answer echoes a request whose name the stub cannot know.

**The fake.** `FakeDynamoDb` is an in-memory DynamoDB behind the same seam, for functional tests; `docs/testing.md` lists the operations and the semantics.

- **Clients and handlers.** `CreateHandler()` is a new `StubHandler` whose responder is `Answer(RecordedRequest)`, with its own `Requests`, `Enqueue` and `ThrowIfResponsesLeft`. `CreateClient(configure)` is `StubClient.Create` over one handler the fake holds for all its clients (system clock: its waits are only its own backoff); `CreateStreamsClient(configure)` is `StubClient.CreateStreams` over the same handler with the fake's clock as `TimeProvider` unless `configure` sets one. The fake's `Requests` and `Enqueue(response)` are that shared handler's: one list per fake, because the code under test makes its own clients and a test asks what the code sent, in order, not through which client; a queued response answers the next request of any of them in place of the fake, and `Reset()` empties both. `Answer(operation, requestJson)` takes the bare name or the whole target, for a server or a raw client. All handlers share the state; one lock covers every request and direct call from start to end; no static state.
- **Stream waits.** The readers' waits on an idle stream (`EmptyPageDelay`, looks for children) also end at the next change of a stream of the fake (a record, split, enable, disable, `Reset`), so a test on the system clock reads a write in milliseconds with the requests real DynamoDB would get; a late child listed by the clock alone and a retry after a failure wait their whole time.
- **Tables.** A table exists only once created: over the wire; by `CreateTable(request)`, with the wire's checks; by `CreateTable<T>(name)`, through `TableSchema` as the entity's `CreateTable()` builds it; by `CreateTable(name, partitionKey, sortKey)`, on demand, string keys, no index (the table of `client.Table(name, pk, sk)`); or by `CreateTable(command)`, which applies an unsent `CreateTableCommand` at once and records no request: its `ToRequest()` (keys, indexes of every `Including`, stream) through `CreateTable(request)`, then time to live on the attribute of `TimeToLive(...)` or the entity; with `IfNotExists()` a table of that name is kept and gets time to live only if it has none (another attribute is drift and changes nothing). Tables and indexes are `ACTIVE` at once, and `DeleteTable` frees the name at once.
- **Items.** `Put`, `Get`, `Delete` and `Items` (entities through `Item.From`/`To<T>`) use the storage path of `PutItem`, `GetItem`, `DeleteItem` without a condition and throw what a client throws for the wire's answer (through `ErrorMapper`). `Get` and `Items` give copies; `Items` is in key order. `Items<T>` of an entity with a discriminator reads only items whose discriminator matches (as `Item.Is<T>()`) and skips the rest, as a typed scan filters; an item of `T` that `T` cannot read throws; an entity without a discriminator or a document reads every item. `Get<T>` reads one key and throws for another entity, as `Get(key).ItemAsync()` does.
- **Forms of the declared table.** The forms without a table name use the name the entity declares, as declared (the fake has no `TableNaming`, so a test whose client sets one passes the name); an entity without one throws the `InvalidOperationException` of `client.Table<T>()`, and `DYNA238` covers these calls. The key forms take a generated key (whose `T` the compiler infers) or the entity's key, without `StubResponse.KeyOf`. `TableItems<T>()` is `Items(name)` (every raw item of that table), `GetItem<T>(key)` is `Get(name, key)` and `PutItem<T>(item)` is `Put(name, item)`, for tests that check or plant unmapped attributes. Named `PutItem`, not `Put<T>(Item)`: beside `Put<T>(entity)` and `Get<T>(Item key)` (which reads an entity) it would read as putting a `T`, and `Put<T>(null)` would be ambiguous; `Item` in the name marks the raw forms.
- **Clock.** The constructor's `TimeProvider` dates tables and stream records; `ExpireItems()` compares the time to live attribute (epoch seconds) with it, leaving expiries more than five years in the past as DynamoDB does, and records its deletes with the service as `userIdentity`; nothing expires otherwise. It also expires shard iterators after 15 minutes, trims records after 24 hours, and removes a shard 24 hours after it closed and a stream 24 hours after it was disabled.
- **Streams.** `EnableStream(table, viewType)` and `DisableStream(table)` are the `StreamSpecification` of an `UpdateTable`, with its checks and `ValidationException`s (enabling an enabled stream, disabling one that is off), and return the description: an enable makes a new stream with new `LatestStreamArn` and `LatestStreamLabel`; a disable closes the open shards, so readers reach their ends and `DescribeStream` says `DISABLED`; a view type outside the four is `ArgumentOutOfRangeException`. A stream starts with one shard; `SplitStreamShards` closes every open shard and opens one or two children of each, which take writes by a hash of the partition key and which `DescribeStream` lists with their `ParentShardId`, the second only after `secondChildListedAfter` on the clock.
- **Failures.** `FailNext(operation, failure, times = 1, when = null)` plans that the next `times` requests of an operation (bare name or whole target) that `when` accepts get `failure` instead of the fake's answer; a request takes the first planned failure that fits, under the lock, so the shard readers of `ReadStreamAsync` take each once; the fake never sees it, so a failed write writes nothing. It applies in both `Answer` methods, so to every handler and client of the fake, also those made before; a response queued on a handler still comes first. `ThrowIfFailuresLeft()` throws `InvalidOperationException` naming what no request took; `Reset()` drops it; the direct API takes none. `when` runs under the lock and must not call the fake; `times` below 1 is `ArgumentOutOfRangeException`. It replaces `new StubHandler(r => r.Operation == "GetRecords" ? error : fake.Answer(r))`, which a test of a lost response still writes, since there the fake must answer.
- **Unsupported.** An operation the fake does not answer is HTTP 400 `UnknownOperationException`; an enum value DynamoDB lacks is its `ValidationException`; an unimplemented member inside an answered operation is HTTP 400 with `__type` `DynaSharp.Testing#UnsupportedByFakeException`, so `ErrorCode` is `UnsupportedByFakeException`. No member is ignored.

**`StubSts`** stands in for STS in tests of how a pod gets credentials or of an assumed role. A provider has its own HTTP client, so it is a server, not a handler: HTTP/1.1 on `127.0.0.1` and a free port, one per instance, listening from the constructor to `Dispose`, no network calls. It answers `AssumeRoleWithWebIdentity` and `AssumeRole` with the next queued response, else `DefaultResponse`, else 400 `StubStsNoResponse`, which the provider puts in its `CredentialsUnavailableException`. `StubStsResponse.Credentials` is the AWS documentation's sample of the requested action with the given values (`AssumeRole` without `SourceIdentity` and `PackedPolicySize`, answers to parameters no provider sends), `AssumedRoleUser` derived from the request's role and session, and `2100-01-01T00:00:00Z` without an expiration, beyond any test clock, so neither the advisory (15 min) nor the mandatory (10 min) refresh opens unless the test gives one. `Error` has the status botocore's model gives the code; of unlisted codes, `AccessDenied`, `InvalidClientTokenId` and `SignatureDoesNotMatch` are 403 as the real service sends them, the rest 400. `new WebIdentityCredentialsProvider(tokenFile, roleArn, sts.Endpoint)` reads no variable, so the test runs in parallel; a test that sets `AWS_ENDPOINT_URL_STS` to `sts.Endpoint` with `AWS_WEB_IDENTITY_TOKEN_FILE` and `AWS_ROLE_ARN` goes through the default chain as a pod does and must not run in parallel. The stub never touches the environment or the disk; the token file is the test's. `new AssumeRoleCredentialsProvider(source, roleArn, options: new AssumeRoleOptions { StsEndpoint = sts.Endpoint, Region = region })` reads no variable either; the stub takes any signature, and `ExternalId` and `DurationSeconds` read the request's form.

## 17. DynaSharp.Coordination

A package of its own, depending on the public API of `DynaSharp` alone, at the version it was built with or later. It holds leases on named locks with fencing tokens and leader election, nothing else (a queue over a sparse index and a hi/lo sequence are recipes). `docs/coordination.md` is the guide.

| Type | Members |
|---|---|

**The current lease.** `await client.TransactWrite().IsHeld().Put(orders, order).SendAsync(ct);` fences a write deep in a leader's work without passing the lease down. `Lease.Current` is an `AsyncLocal<Lease?>` set by `RunAsLeaderAsync` before it calls the work of a term and cleared in the term's `finally`, with no public setter (leases of `TryAcquireAsync`/`AcquireAsync` are passed explicitly). It flows into what the work calls and starts during the term, never back to the caller. Code started before the term (a constructor, `StartAsync`), under `ExecutionContext.SuppressFlow`, or in the heartbeat (started at the acquire with a suppressed flow) sees null, and `IsHeld()` there throws `InvalidOperationException`: "No lease is current; pass the lease, or start this work inside RunAsLeaderAsync." Work that outlives its term keeps the ended lease, and `IsHeld()` fails its transaction at DynamoDB, which is the fencing. In a nested `RunAsLeaderAsync` the inner lease is current. The lease is read when the step is added.

**The item.** A lock is one item of the given table: partition key `LOCK#` + name, sort key `LOCK` if the table has one, both strings. Attributes, frozen as the stored format: `_type` (`LOCK`), `owner` (new id per acquire, absent while free), `rvn` (new id per acquire and renewal), `fence` (`ADD` 1 per acquire), `leaseMs` (absent while free), `holder` (the acquiring `LockTable`'s `HolderLabel`; removed by an acquire without one and by a release; diagnostic only, never in a condition, read as none when not a string). An item with an `owner` whose `owner` or `rvn` is no string, `leaseMs` no whole number from 1 to 86400000, or `fence` no whole number from 0, makes an acquire throw `InvalidOperationException` naming lock and table. A release keeps the item; without `TimeToLiveAttribute` there is no expiry, so the token goes back only if the item does (deleted, to 1; or restored from a backup or point in time). With it, every acquire, renewal and release (and `SimulateHolderAsync`, `SimulateReleaseAsync`) sets that attribute to the client's `TimeProvider.GetUtcNow()` in epoch seconds plus `TimeToLiveRetention`; the user turns the table's time to live on. A lease renews at least every 8 hours and the retention is at least a day, so a held item is not due unless the holder's wall clock is off by more than retention less lease. An item time to live deleted restarts the token at 1: fencing across that gap is not guaranteed (documented). The lock table must have a single writing region: a global table written in two can grant a lock twice with one token.

**Leases.** The duration runs from 1 s to 1 day, else `ArgumentOutOfRangeException`, stored in whole milliseconds rounded up. A lease is held from when its acquire was sent, for its duration on the client's monotonic clock (`TimeProvider.GetTimestamp`); each successful renewal extends it to a duration after that renewal was sent, unless a later-sent renewal already did, so a late answer moves nothing. This holds for any offset between hosts' clocks and assumes equal rates; a suspended host can wake on an ended lease, which `IsHeld` and the token are for. The heartbeat renews a third of the duration after the last successful renewal was sent (first after the acquire was sent), so answer latency does not delay the next. It runs without the acquiring caller's execution context: no async locals, each renewal span a root linked to the acquire span. A renewal is an `UpdateItem` writing a new `rvn` on `owner = :me`. `Ended` is cancelled when a renewal fails its condition on an item with another owner (`taken_over`) or no item (`deleted`, read from `ReturnValuesOnConditionCheckFailure`), on `ResourceNotFoundException` (`table_not_found`), when the lease runs out without a successful renewal (`expired`), and by `DisposeAsync`. A heartbeat renewal failing otherwise (after the client's retries) is retried after 100 ms, doubling up to a sixth of the duration, until one succeeds or the lease runs out; log 42 each time. Losing is final. `RenewAsync` sends one renewal: `false` for an ended lease, `ResourceNotFoundException` with the lease lost, any other client error with the lease still held, `OperationCanceledException` for its own token with the lease kept. `DisposeAsync` stops the heartbeat and removes `owner` and `leaseMs` on `owner = :me`; a failed condition is ignored, other failures logged, not thrown; a second call does nothing. An undisposed lease is renewed for the life of the process. An acquire answered after a whole duration returns an ended lease.

**Acquire and takeover.** A `LockTable` with a sighting of the lock (a remembered holder) first reads the item with a strongly consistent `GetItem`: a holder with another `rvn`, or the same `rvn` seen for less than a whole lease of the holder on the monotonic clock, is remembered and the try ends without a write; a free item (no `owner`), or the same `rvn` for a whole lease, goes on to the write. Without a sighting the try writes at once. The write is one conditional `UpdateItem` with `ReturnValues ALL_OLD` and `ReturnValuesOnConditionCheckFailure ALL_OLD` that sets the attributes and `ADD`s the token, on `owner` not existing or, for a holder due for takeover, `rvn` still the one seen. The old item gives the token (its `fence` + 1) and whether a holder was displaced (an `owner` in it), which alone counts and logs as a takeover. A failed condition takes the item from the answer, or where none came (an emulator) reads it strongly consistent: an `owner` equal to this acquire's means a retry after a lost response, and the lease is held with the item's token; else the holder is remembered. A `TransactionConflictException` (a transaction on the lock item, such as the holder's `IsHeld`; the client never retries it) is handled as a failed condition without the item: a strongly consistent read, then the same rules, so it is a refusal (`null`, or a wait of `AcquireAsync`) and never reaches the caller; the transaction writes no `rvn`, so the sighting stays as it was. So a contender waiting on a live holder sends one read per poll and no write; failed conditional writes happen when a `LockTable` first meets a held lock and when contenders race for a free or due one. `TryAcquireAsync` returns `null` then and never waits, so only a `LockTable` living longer than a lease takes over a crashed holder with it; a short-lived process calls `AcquireAsync` with a token that cancels after more than a lease. `AcquireAsync` waits a third of the holder's lease, at most 10 s, or less if the lease runs out sooner, and tries again until cancelled; with `wait` it waits at most what is left, tries once more at the end, then throws `TimeoutException`, so no request in flight is cut off and the call ends late by at most its last request. A `LockTable` is thread-safe and its memory of holders is per instance, so a process holds one per table. A sighting older than ten of its holder's leases counts as none, and a sweep, at most every 10 s on the client's clock when a try remembers a holder, drops those: a try that finds a sighting a lease old takes over or replaces it, so one that old saw no try for nine leases, and a contender that gave up per job does not keep them forever. A try within ten leases keeps its sighting, so a retried message on the same pod still takes over a crashed holder; a later one watches a whole lease again.

**Fencing.** `IsHeld(lease)` is a `ConditionCheck` on the lock item with `owner = :owner AND fence = :token`, so the transaction commits only while this lease holds the lock. A lease that ran out locally still passes while nobody took the lock over. Systems outside DynamoDB compare `FencingToken` themselves.

**Leader election.** `RunAsLeaderAsync` checks its arguments in the task it returns, acquires with `AcquireAsync`, runs `work` with a token linked to the caller's and to `Ended`, and releases after each term. A lease already ended when its acquire returns starts no term. A term whose lease was lost contends again, whatever the work returned or threw. The caller's cancellation releases and throws `OperationCanceledException`, whatever the work did; what it threw is logged at Debug (48). Work that returns or throws on its own releases and returns or rethrows. A transient acquire failure (`IsTransient`, `TimeoutException`, `HttpRequestException`, `CredentialsUnavailableException`) is counted and retried after a third of the lease; the first of a row logs a warning (44) and the next try DynamoDB answers (free or held) an information (49) with time and retries, so an outage logs two lines however long; any other error ends it. It ends when the work ends; a service that leads while it runs loops around it, and `docs/coordination.md` has a `BackgroundService` recipe: the work catches its own faults while its token is not cancelled, so the loop logs, pauses and contends again; an election error (non-transient acquire failure) leaves `ExecuteAsync` and stops the host through `BackgroundServiceExceptionBehavior.StopHost`; shutdown returns.

**Telemetry.** The client's `DynaSharp` activity source and meter. Spans `Lock.TryAcquire`, `Lock.Acquire`, `Lock.Renew`, `Lock.Release` (`Internal`, parents of their requests' spans) with `db.system.name`, `db.collection.name`, `dynasharp.lock.name`, and on an acquire `dynasharp.lock.acquired`, `dynasharp.lock.takeover`, `dynasharp.lock.fencing_token`; a failure sets `error.type` and status `Error`; renewals and release link to the acquire span. Counters `dynasharp.lock.acquisitions` (`{lease}`, with `dynasharp.lock.takeover`), `dynasharp.lock.renewals` (`{renewal}`, `error.type` on failure), `dynasharp.lock.losses` (`{lease}`, `dynasharp.lock.loss_reason`) and `dynasharp.lock.contention_retries` (`{retry}`, `error.type`, one per transient acquire failure of `RunAsLeaderAsync`, also while log 44 is quiet), each with `db.collection.name` and without the lock name. Logs in category `DynaSharp.Coordination.LockTable`, ids 40 to 49 (`docs/coordination.md`); 41 names the holder labels before and after a takeover, 45 and 46 this process's label (`(null)` without one). No key value, item or attribute value; the lock name, on spans and in logs, is the one accepted exception, a name chosen in code that operators need. The holder label is in logs only.

## Table administration and conflicts

**`CreateTableCommand`.** `orders.CreateTable().Including<Customer>().SendAsync(ct)` creates a table from what the entities declare: one entity cannot describe a single-table schema, so the indexes are the union over the entities named. `Including` throws `ArgumentException` when two entities give an attribute two types or declare different `[TimeToLive]` attributes (a table has one). `Provisioned(read, write)`, `Stream(view)`, `TimeToLive(attribute)`, `WaitUntilActive()` (5 minutes) or `WaitUntilActive(timeout)`, `IfNotExists()` and `Timeout(timeout)` shape it; an entity's `[TimeToLive]` is a `TimeToLive` the chain does not name, and an explicit `TimeToLive(...)` replaces it. `ToRequest()` hands over a `CreateTableRequest` for what the command does not cover (tags); `ToRequestJson()` renders it. A custom converter on a plain key counts as a string unless it implements `IAddableConverter`. `SendAsync` and its awaiter return `CreateTableResult` (sealed): `Table` (the `TableDescription`), `Created` (this call's `CreateTable` created it; false when `IfNotExists()` found it, also after a lost response whose retry met the table), `TimeToLiveEnabled` (this call's `UpdateTimeToLive` was accepted; false when already on, on another attribute, not asked, or another instance got there first) and `Drift` (`IReadOnlyList<TableDrift>`, empty for a created table). `TableDrift` is a positional sealed record: `Kind` (`TableDriftKind`: `IndexMissing`, `IndexDiffers`, `TimeToLiveDiffers`, `StreamDiffers`), `IndexName` (`string?`, for the index kinds) and `Description`, naming table, expectation, what the table has, and what follows. `docs/tables.md` is the guide.

**`IfNotExists()`** describes first: a table that is not `DELETING` ends the create without `CreateTable`, so an existing table needs `dynamodb:DescribeTable` alone and leaves no failed call in CloudTrail (unless `TimeToLive` is on the chain, which goes on and needs `dynamodb:DescribeTimeToLive` and `dynamodb:UpdateTimeToLive`); with `WaitUntilActive()` a first look that shows everything active needs no other. A missing or `DELETING` table goes on to `CreateTable`, so creating needs both permissions; any other error of the first look surfaces. It checks a found table against the command from that description, with no further call. A different key (partition or sort key name, presence of a sort key, or `S`/`N`/`B` type where both sides know it; a table opened without an entity knows names only, `ScalarAttributeType.Unknown`) throws `InvalidOperationException` naming table, expected and found key, before any wait or time to live; so does one a create loop finds after `ResourceInUseException`. A description without a key schema is not compared. What lets part of the code work is drift, in the result and logged once (event 14, Warning): a declared index missing, or with other keys or of the other kind; time to live on another attribute; with `Stream(view)` a stream that is off or of another view. What the table has beyond the command is no drift. The command changes none of it. A `DELETING` table is no success: the `ResourceInUseException` surfaces, with and without a wait. When `CreateTable` says `ResourceInUseException` and `DescribeTable` then finds no table (a delete that just ended, or a table another process just created), the command creates again, up to 5 times over 1.5 s, before the exception surfaces.

**Streams, time to live, indexes.** `Stream(view)` goes into the request (`ToRequest()` shows it) and applies to a table the command creates; under `IfNotExists()` an existing table's stream is untouched. A value that is no view throws at the clause. `TimeToLive(attributeName)` and `TimeToLive(Attr)` (a generated handle converts to it; a nested path is refused) ensure time to live after the create or after finding the table, and are not in `ToRequest()`, since `CreateTable` does not take it. It needs an active table, so it implies the wait (default timeout unless `WaitUntilActive(timeout)` gave one), which a missing declared index times out. Then `DescribeTimeToLive`: `ENABLED` or `ENABLING` on that attribute ends it; on another attribute it ends too, without `UpdateTimeToLive`, as `TimeToLiveDiffers` drift; anything else sends `UpdateTimeToLive`. Its `ValidationException` (what a second instance gets when the first won) looks again: time to live now on, for that attribute or as drift for another, is success, else it rethrows. It needs `dynamodb:DescribeTimeToLive`, `dynamodb:UpdateTimeToLive` when not on yet, and `dynamodb:DescribeTable` for the wait. Indexes, like the stream, apply to a table the command creates. An index for an existing table goes in this order (the README shows it): `CreateTable().IfNotExists()` without a wait; `WaitUntilActiveAsync` on `client.Table(name, "pk", "sk")`, which declares nothing, because `UpdateTable` needs an active table and a typed wait times out on an index not there yet; `UpdateTableAsync`, one index per call; last the typed wait, with a timeout that fits the backfill. `TimeToLive` implies that wait, so it goes on the last step.

**Timeouts.** `WaitUntilActive(timeout)` bounds the wait alone: the calls before it and time to live after it take their own time. `Timeout(timeout)` bounds all of `SendAsync` on the client's `TimeProvider` (the look of `IfNotExists()`, `CreateTable` with its retries and repeats, the wait, time to live): when it runs out the call in flight is cancelled and `SendAsync` throws `TimeoutException` naming the table, the timeout and the step (looking for the table, creating it, waiting for it, turning time to live on, describing it), the `OperationCanceledException` inside. A wait whose own bound runs out first throws `TableNotActiveException`, an attempt out of `AttemptTimeout` its own `TimeoutException`, and the caller's token wins with its own `OperationCanceledException`. It adds no wait. The value is above zero and at most 4294967294 ms, or `Timeout.InfiniteTimeSpan`; anything else is `ArgumentOutOfRangeException` at the clause. A table DynamoDB accepted stays after a timeout. `DeleteTableAsync` deletes all items and does not wait.

**`RetryOnConflictAsync`.** `orders.RetryOnConflictAsync(ct => ..., ct)` runs a delegate again on `ConditionalCheckFailedException`, `TransactionConflictException` and a cancelled transaction with those reasons, up to 5 runs by default, with a small jitter (10 ms doubling, at most 1 s) on the client's `TimeProvider`. It is a member of `Table<T>` alone, because the table is what a caller holds; the table only supplies the client whose clock and telemetry the loop uses, so a run can write other tables and send transactions. Two delegate shapes, `Func<CancellationToken, ValueTask<TResult>>` (and `ValueTask`) and the same with the run number first, each in two forms, eight members: `(operation, ct)`, and `(operation, retryOn = ConflictKind.Any, maxAttempts = 5, onConflict = null, ct = default)`. The first form lets the token go positionally after the delegate; the second takes the rest by name (`RetryOnConflictAsync(op, ConflictKind.TransactionConflict, cancellationToken: ct)`), and a call with only the delegate binds to it. A literal `0` in second place converts to `ConflictKind` and throws `ArgumentOutOfRangeException` naming `retryOn`. `retryOn` is the `[Flags]` enum `ConditionalCheckFailed`, `TransactionConflict` or `Any` (default); a conflict it does not name surfaces at once like any failure, with no wait and no conflict telemetry; a cancelled transaction runs again when any of its reasons is of a named kind; another value throws `ArgumentOutOfRangeException` at the call. `TransactionConflict` alone is for a run whose failed condition is its answer (a uniqueness claim, a record that exists). `onConflict` (`Action<int, DynamoDbException>?`) gets the losing run's number and exception before the wait, for each conflict another run follows, never the last; it is synchronous because a log is its purpose, and its exception surfaces in place of the conflict and ends the retries. The run number (1 first) lets a value read before the call serve the first run while later runs read again, without a variable the delegate clears; the shapes pair like LINQ's `Select(x => ...)` and `Select((x, i) => ...)`, picked by the lambda's parameter count, and `DYNA218` follows both. Nothing else retries a conflict. The delegate must read again, or the retry changes nothing. A conditional write whose response is lost fails its own pipeline retry and the helper applies the change again: `.MaxAttempts(1)` on the write avoids that. Follow-up writes stay outside the delegate: a retry inside multiplies runs, and one that gave up counts as a conflict of the outer one. What surfaces after the last run is that run's exception, so a `ConditionalCheckFailedException` holds the `Key` of that run's write (section 15).
